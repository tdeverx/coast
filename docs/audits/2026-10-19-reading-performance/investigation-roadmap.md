# Reading delivery investigation roadmap

19 October 2026. **Research backlog: no delivery redesign is approved or implemented.** The current requested implementation is loading feedback, the default-on odd-face preference and reading integration fixes. Follow [performance.md](../../performance.md); retain the [audit baseline, failures and measurements](README.md).

## Candidates to benchmark

- [ ] **RD-01 — session-owned compressed input reuse.** Compare current open/minimize/resume/close against bounded reuse of the exact authorized file. Measure first-open/resume latency, transferred bytes and peak/settled browser memory. Specify byte/expiry ownership, replacement, close, disconnect and capability withdrawal. Preserve current permissions and avoid retaining decoded pages/GPU resources just to save a download.
- [ ] **RD-02 — version-bound page manifest.** Record ordered entries, dimensions, split-face mapping and original locations. Compare cold creation and warm reuse separately; invalidate on source version/account changes. Three.js currently requires whole-document dimensions, so page streaming alone does not remove its inspection barrier. Never guess a changing page count/order from a few initial images. [Readium's manifest model](https://github.com/readium/webpub-manifest) is a reference, not a new dependency decision.
- [ ] **RD-03 — ZIP/CBZ selective byte-range loading.** Prototype with existing [zip.js HttpRangeReader](https://gildas-lormeau.github.io/zip.js/api/classes/HttpRangeReader.html), the same manifest/permissions and bounded range reuse/prefetch. Compare complete entry, first usable page, near/far/back turns, request count, actual transferred bytes and cancellation. Preserve the earlier adverse small-request range results; do not repeat that design under a new name. Admit a natural within-cap and oversized actual CBZ when available.
- [ ] **RD-04 — plain TAR/CBT indexing.** Test header/offset indexing and requested-entry ranges using the [documented TAR structure](https://www.gnu.org/software/tar/manual/html_node/Standard.html). Handle extended headers, paths and sizes correctly; compressed TAR wrappers are separate. Compare cold indexing, warm indexed reads and server/provider request overhead, not just requested image size.
- [ ] **RD-05 — RAR/CBR and 7z/CB7 demand decoding.** Census actual solid/non-solid archives. Compare early/late/random/backward entry reads and bounded block reuse. [RAR solid dictionaries](https://www.rarlab.com/technote.htm) can depend on previous files; the [7-Zip SDK](https://github.com/ip7z/7zip/blob/main/DOC/7zC.txt) describes decoded solid-block caching. One returned page does not imply one page of network/CPU/memory work. The existing [libarchive-wasm input API](https://github.com/ofk/libarchive-wasm) is an in-memory byte array, not an already available asynchronous HTTP range adapter.
- [ ] **RD-06 — companion-side manifest/page delivery across formats.** Evaluate local-file access through the existing Jellyfin companion against a Coast-side range-backed extractor. [SharpCompress](https://github.com/adamhathcock/sharpcompress) offers .NET ZIP/RAR/7z/TAR extraction APIs; [archive-proxy](https://github.com/Heng-Bian/archive-proxy) is a remote range-backed implementation reference. Neither is approved or performance-certified for Coast. Compare cold extraction and warmed bounded caches, multi-reader contention, late solid pages, revocation, cancellation and cleanup. Do not add a service/dependency or storage owner without a reviewed decision.
- [ ] **RD-07 — existing page-delivery protocols.** Study [Komga page APIs](https://komga.org/docs/openapi/book-pages/) and [OPDS-PSE](https://vaemendis.net/opds-pse/) as references for ordered manifests, page URLs and optional resized images. Preserve original bytes/quality by default and keep explicit Coast progress commands separate from speculative image requests. The inspected [official Jellyfin OPDS controller](https://github.com/jellyfin/jellyfin-plugin-opds/blob/master/Jellyfin.Plugin.Opds/OpdsApi.cs) provides feeds/covers/downloads, not verified archive-page extraction. Do not equate ordinary OPDS with PSE support.
- [ ] **RD-08 — startup stage attribution.** Measure preparation, transfer, archive enumeration, inspection, required rasters/textures, shader/model setup and entrance separately. Then compare safe overlap at the existing owners while preserving demand loading, animations and error/cancel behavior. Loading feedback is not a speed improvement.

## Known delivery evidence and gaps

The actual configured server reported Jellyfin **12.2.0**. Both `/Items/{id}/Download` and `/Items/{id}/File` returned correct 1,024-byte prefix/suffix ranges (206, matching byte hashes) from an actual 82,635,611-byte CBR. This establishes range capability on that file, not archive-entry efficiency or a faster endpoint. Its live `/api-docs/openapi.json` returned **500**: complete installed-endpoint discovery remains unresolved. Standard provider GET download logging may occur even during capability checks.

The initial audit has five actual CBRs and no usable natural PDF/EPUB/CB7/CBT or sampled within-cap CBZ acceptance. Five then-current CBZs were 402–635 MB and rejected by the existing 128 MiB cap. Keep those gaps explicit; do not replace them with generated catalogue records or claim current safety limits can simply be raised. Physical presentation on a narrow desktop viewport is not hardware mobile acceptance.

## Acceptance and stopping rules

- [ ] Use actual catalogue/admin identities and actual images. Label controlled states/packaging and use owned actual-data copies for destructive/failure controls; no fabricated provider responses count as acceptance.
- [ ] Freeze source, input hashes, dependency versions and cache state; warm up, alternate variants and preserve every error/adverse sample.
- [ ] Compare complete original page identities/order/pixels/bookmarks and both odd-face preference modes. Check exact edition identity, separate participant source access and canonical party locations.
- [ ] Include time to the actually usable reader, not a cover preview alone. Measure total bytes, provider calls, decoder work, browser/server CPU, peak/settled memory and any disk/WAL costs introduced.
- [ ] Close/replace/minimize/reopen and cancel pending downloads/decodes. Verify revocation, bounded concurrent readers, no speculative progress writes and no new Activity flood.
- [ ] Benchmark the smallest shared candidate first. Retain defaults when gains are mixed/absent; rejected methods return to the investigation backlog rather than triggering unbounded alternative searches.
- [ ] Present options/results before adoption. Update current methods and source epochs without overwriting historical receipts.

Prioritize RD-01 and the RD-02/RD-06 design comparison; RD-03 is the focused existing-library alternative. Leave the rejected native micro-batching method behind uninvestigated stages until new evidence justifies another trial.
