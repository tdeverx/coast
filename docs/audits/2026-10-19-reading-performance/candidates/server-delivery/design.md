## Proposed dependency decision

Use a small isolated native helper built against **libarchive** for streamed ZIP/RAR/7z/TAR reading, and **sharp** for bounded image metadata (including image orientation) on the server. libarchive is already the underlying codec family in the current browser WASM dependency and the successful native benchmark, but native production packaging is new. sharp is a new production package. No plugin/service is required. The production container would build the helper with libarchive headers and ship its native runtime library; development uses the same helper against the installed system library. This needs explicit approval under the supplied AGENTS rule before dependency changes.

The helper is necessary to expose structured entry metadata/types and bounded original page bytes rather than parsing `tar -t` text or trusting extracted paths. It never writes archive-supplied paths: only ordinal page filenames inside an application-created private directory. Enforce the existing entry/expanded/page/container/encryption/path policies, cancellation and process deadlines. JSON event output must be bounded. Image dimensions are header metadata, not a server rasterization/re-encoding pipeline; original image bytes remain unchanged. Preserve browser image/pixel admission on requested pages as well.

## Shared owner and lifecycle

- One process-owned cache, keyed by verified provider instance/file/version/format, coalesces concurrent acquisition for personal and party sessions. A cache key is never an access grant. Each manifest/page request rechecks its owning reading session, live provider access/version, feature/category policy and account generation through the existing reading owner.
- Stream the authorized download to temporary disk and the isolated extractor with backpressure. Build ordered page dimensions and hashes on the server. Retain original encoded images, not decoded pixels, in private numbered page files. Serve a completed page only after its bytes/metadata are verified. Do not invoke the whole-array WASM decoder server-side.
- Cold manifest preparation completes the full order/dimension metadata before publishing a Three.js layout. The client uses that metadata to map faces without extracting or decoding every page. Its eight-raster/twelve-face/four-turn ownership remains unchanged. A bounded exact-version manifest record may support overlap on subsequent acquisition; never guess cold layout or claim first-page microbenchmarks are full reader readiness.
- Active session leases share files. Closing releases only that session; remove files after the last lease releases. Minimize releases renderer/GPU resources while its session lease has a bounded heartbeat expiry; resume reacquires if expired. Abandoned sessions, partial failures, cancellation, source revocation, capacity pressure and process restart must clear temporary data without deleting another live reader's files.
- Bound global disk/free-space admission, cache record count, preparation concurrency and idle leases. Limits constrain total resources, not an arbitrary restored per-file download cap. Avoid an unbounded wait queue, per-card calls, per-page jobs or durable progress writes from speculative page requests. Share one expiry/cleanup timer; remove startup leftovers under the dedicated cache root.
- PDF keeps its existing selected-page range renderer (it already has no full-document raster scan). EPUB keeps reflow and sanitization. Local user-supplied files remain browser-owned. Remote comic archives use the shared manifest/page path automatically, including party matching; do not retain an automatic browser-whole-archive fallback after server failure.
