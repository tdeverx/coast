## Result and measured tradeoffs

Remote Jellyfin comics now share a temporary server cache and complete dimension manifest across personal and party readers. Acquisition/extraction overlap for ZIP/RAR/TAR; 7z requires seekable download-first input. Three.js keeps its existing presentation/layout and requests original encoded pages on demand. The browser no longer downloads/extracts the whole remote archive or decodes every scan merely to discover dimensions. Local files, PDF ranges and EPUB retain their format-specific owners. No schema migration or Jellyfin plugin is introduced.

A serial actual-admin/live-provider comparison of the immutable baseline and current physical reader used one warm-up pair and three alternating timed pairs on the same 73,339,323-byte CBR. Each timed close deleted its last server byte lease, while exact-version manifest metadata remained warm. ## Shared ownership and limits

`reading/cache.server.ts` owns one exact provider-instance/file/edition/format acquisition, encoded ordinal page files, leases and retained metadata. `sessions.server.ts` remains authoritative for per-reader access and live version checks. `delivery.server.ts` exposes one cancellable NDJSON progress/manifest response and original page streams. `reader/remote-comic.ts` validates presentation metadata and bounded body sizes; the existing physical layout retains spread/odd-face/location mapping.

The helper writes only app-generated `page-N` files under private app-created directories. It rejects invalid/duplicate paths, mismatched containers, encrypted/damaged input and entry/expansion/page overflow. ZIP central-directory image membership/sizes must agree with streamed output. PNG/JPEG/GIF/WebP signatures are admitted before sharp; header dimensions include orientation and the browser's 2048-longest-side rounding. Original encoded bytes and requested browser pixel admission remain unchanged. Unsupported inputs fail explicitly, without an automatic whole-file fallback.

One process exclusively owns each cache root. The free-space check conservatively includes every outstanding reservation, including materialized bytes already reflected by filesystem free space; it can reject earlier on a nearly full disk. Source bytes plus a 512 MiB expansion allowance are reserved before writing; total reservations are at most 8 GiB with a 512 MiB free-space floor. At most two preparations and 64 session leases are admitted globally; one account can hold at most eight delivery leases. Cold jobs use the global two-preparation pool without an extra per-account gate. Renewal and sharing an existing source remain admitted. Checks reuse bounded existing maps without database work or a wait queue. This prevents one account from indefinitely occupying the entire pool; coordinated accounts can still reach the global bound. Foreground heartbeats renew three-minute leases; one 30-second sweep expires abandoned owners. Closing the last lease aborts/drains extraction and removes temporary bytes before returning reservations. Closing one participant preserves another's files. Startup removes only abandoned app `run-UUID` entries; symlink cleanup does not follow the target.

Retained exact-version metadata expires after 30 minutes and is bounded by 64 records, 100,000 pages and 16 MiB estimated metadata, with a separate 32 MiB estimated active budget. These are accounting bounds, not measured heap ceilings. A retained manifest allows early layout during reacquisition; original page hash/size/dimensions must verify before that page is served. Failed preparation evicts metadata and releases its leases. Last close still deletes original page/archive bytes, so later reopening downloads again. Minimize disposes GPU resources while its session's byte lease expires naturally.

The native helper has 30 seconds CPU and, on Linux, 512 MiB address space. macOS lacks that address-space enforcement. Provider stream idle/cancellation limits remain in force. Sharp metadata executes inside the coordinator; there is no claim of a hard whole-process or process-tree memory cap. See [performance methods](../../performance.md#physical-reader-ownership) and [operation/build commands](../../reading.md#server-comic-delivery) for the maintained contract.

## Reverse exit animation

The requested physical-reader exit reuses the entrance pose in reverse: close an open cover, return from a focused/rotated view, rotate away and descend. Normal close, Escape, backdrop dismissal and Show app use the same registered engine transition before destroying the renderer. A duplicated exit shares one operation. Presentation-only closing is muted from bookmark/party callbacks. A failed bookmark flush leaves the reader visible before exit; revocation bypasses animation. Closing during pending construction/turns still cancels immediately. Disposal settles tracked animation promises and removes scheduled frames; hidden/reduced-motion transitions finish without optional motion.

Actual normal-browser exit remains visible partway through, then removes the physical host and loses that reader's WebGL context, while unrelated app contexts remain alive. These are lifecycle observations, not guaranteed durations; the app's complete close can also wait for bookmark/network work. The original entry comparison above predates the later staged-entry addition and retains that measurement epoch.

## Codex review follow-up

The first code review identified concurrent free-space overcommit (P1) and stale inspection counts (P2). Both reproduce against commit `191ed7e` using the actual first CBR: simultaneous reservations both passed a controlled filesystem floor that could admit only one, and delayed real sharp inspection ended at 6 rather than 24 reported pages. The fixes check all reservations against free space and update the inspection count after every verified page. Both actual-data regressions now pass, alongside the complete six-file/400-scan byte check (36 cache cases). The slowed metadata case is a controlled scheduling test, not a performance sample. Extra authored regressions bring the application suite to 887 passes/718 guarded skips/zero failures. The first security review had no findings; final PR review/CI status remains on GitHub. Media layout and encoded bytes are unchanged by these admission/progress repairs, so the earlier complete rendered equality and entry measurements retain their stated epoch and scope.

The second security review identified account monopolization of all shared delivery leases (P2). The per-account admission rules above address that finding. The actual-data restore verifies lease rejection/renewal/guest access and release/replacement. An initial additional one-cold-preparation-per-account restriction caused real normal-dev reopen/switch failures, including the user report, and was removed. An actual-file controlled test now admits both personal preparations, closes/reopens the original while preserving a guest, and reacquires it after its last lease closes; global preparation capacity remains bounded. Authored scheduling covers the same admission boundary. These are delivery-resource limits, not new durable bookmark/session-row limits.

Live one-byte range probes explain the later size question: Boss Bitches is 83,732,645 bytes, Journey to Love 82,635,611 bytes and Choose Your Fighters 107,153,476 bytes. Repeated same-edition opens can reuse retained metadata and held pages; warm-manifest reacquisition can show covers before background archive completion. Visible readiness is not a zero-transfer guarantee. Display derivatives would require a separate quality/CPU/bytes/cache benchmark; this pass preserves original encoded images.
