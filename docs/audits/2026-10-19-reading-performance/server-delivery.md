## Shared ownership and limits

`reading/cache.server.ts` owns one exact provider-instance/file/edition/format acquisition, encoded ordinal page files, leases and retained metadata. `sessions.server.ts` remains authoritative for per-reader access and live version checks. `delivery.server.ts` exposes one cancellable NDJSON progress/manifest response and original page streams. `reader/remote-comic.ts` validates presentation metadata and bounded body sizes; the existing physical layout retains spread/odd-face/location mapping.

The helper writes only app-generated `page-N` files under private app-created directories. It rejects invalid/duplicate paths, mismatched containers, encrypted/damaged input and entry/expansion/page overflow. ZIP central-directory image membership/sizes must agree with streamed output. PNG/JPEG/GIF/WebP signatures are admitted before sharp; header dimensions include orientation and the browser's 2048-longest-side rounding. Original encoded bytes and requested browser pixel admission remain unchanged. Unsupported inputs fail explicitly, without an automatic whole-file fallback.

One process exclusively owns each cache root. The free-space check conservatively includes every outstanding reservation, including materialized bytes already reflected by filesystem free space; it can reject earlier on a nearly full disk. Source bytes plus a 512 MiB expansion allowance are reserved before writing; total reservations are at most 8 GiB with a 512 MiB free-space floor. At most two preparations and 64 session leases are admitted globally; one account can hold at most eight delivery leases. Cold jobs use the global two-preparation pool without an extra per-account gate. Renewal and sharing an existing source remain admitted. Checks reuse bounded existing maps without database work or a wait queue. This prevents one account from indefinitely occupying the entire delivery-lease pool; coordinated accounts can still reach the global bound. Foreground heartbeats renew three-minute leases; one 30-second sweep expires abandoned owners. Closing the last lease aborts/drains unfinished extraction. Completed encoded pages remain shared for a 30-minute idle window, retaining their disk/metadata charges; expiry/eviction/shutdown remove files before returning reservations. Active plus idle entries are capped at 64, and resource pressure evicts oldest idle entries before rejecting new work. Active readers are never chosen for idle eviction. Closing one participant preserves another's files. Startup removes only abandoned app `run-UUID` entries; symlink cleanup does not follow the target.

Retained exact-version metadata expires after 30 minutes and is bounded by 64 records, 100,000 pages and 16 MiB estimated metadata, with a separate 32 MiB estimated active budget. These are accounting bounds, not measured heap ceilings. Retained metadata validates original page hash/size/dimensions on reacquisition. The browser manifest stream now waits for completed preparation and continues real progress when only metadata is cached. Failed preparation evicts metadata and releases its leases. Completed page-cache hits avoid archive acquisition until idle expiry or pressure eviction. Restart/server-module replacement clears the temporary cache. Minimize disposes GPU resources while its session's byte lease expires naturally.

The native helper has 30 seconds CPU and, on Linux, 512 MiB address space. macOS lacks that address-space enforcement. Provider stream idle/cancellation limits remain in force. Sharp metadata executes inside the coordinator; there is no claim of a hard whole-process or process-tree memory cap. See [performance methods](../../performance.md#physical-reader-ownership) and [operation/build commands](../../reading.md#server-comic-delivery) for the maintained contract.
