# Invite and account management verification

Verification on 15 November 2026 used Bun 1.4.4 canary `963452075`, PostgreSQL 17.11, a disposable Jellyfin 12.4.0 instance and a local production build. The [source refresh](source-refresh.json) identifies the exact successor to each affected historical source pin. Each dated hosted receipt continues to describe its original run.

- The database suite passed 714 tests with three fixture-dependent skips. The backup test produced an encrypted archive with PostgreSQL's `pg_dump`, decrypted it, restored it with `pg_restore`, and matched the database row and both app files. Both tools came from the disposable PostgreSQL instance. The focused invite suite also verified that reconnecting to the same Jellyfin GUID preserves the account generation and available titles.
- PostgreSQL fixtures verified that onboarding status uses the current account generation even when an obsolete authentication failure has a later timestamp. Status checks project the current job and checkpoint in one database read, without opening the provider credentials. Existing pending jobs stay read-only on subsequent status checks. The quota check rejects exhausted issuers before Jellyfin reads, and the write transaction still checks the quota under lock. Rotating an unclaimed member code retains its original issuance and quota allocation.
- Chromium at 1440 × 900 and 390 × 844 exercised administrator preset and invite creation, signup through the legacy invite route, removal of the secret from the URL and completion of onboarding to Library. The flow generated nine admin API requests across the tab visits and save actions, with zero unhandled page errors. The inventory and production build cover the existing Settings, navigation and auth control composition.
- On disposable Jellyfin, a managed account received a verified library and access schedule. Its allowed title prepared and reported progress with HTTP 200, and the stream returned a 1,024-byte HTTP 206 response. The withheld title returned HTTP 404 for detail and playback. Suspension rejected the existing Jellyfin token and further sign-in, and restoration allowed sign-in again. This run covers the changed permissions path with a direct video source. Hosted HLS, multi-device playback and production latency are outside this receipt.
- The warm restricted Library probe used 12,000 generated titles with 10,000 accessible to one member. A 60-card page took 42.7 ms median across eight measured reads after one warm-up. The harness asserted the page bound and continuation cursor. This sample describes the isolated synthetic catalogue.
