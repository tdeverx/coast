# SvelteKit 3 migration — 21 October 2026

This is the separate framework migration following merged PR #46. It adopts SvelteKit **3.1.0**, official `@sveltejs/adapter-bun` **1.0.0** and TypeScript **6.0.3**. The selected shipping Bun canary/image stays unchanged. TypeScript 7 is not adopted: its missing compiler API is incompatible with the Svelte checker and Coast's inventory tools. This pass changes framework integration, not the approved interface or provider/database policies.

## Runtime origin remains the deployment contract

The user explicitly chose to retain runtime `ORIGIN` rather than require a new proxy or rebuild per installation. Compose continues to set the exact address users open. One image supports a configured LAN HTTP origin or public HTTPS origin. It does not automatically choose between two origins or classify a visitor as LAN/WAN. Public TLS still terminates at the installation's existing proxy.

The official adapter otherwise only supports a build-time origin or forwarded scheme/host headers. The small maintained [adapter patch](../../patches/sveltejs-adapter-bun-1.0.0.patch) reads the existing runtime variable, including the adapter's optional environment prefix; validates HTTP(S), rejects credentials/path/query/fragment, and canonicalizes the origin. A trailing root slash remains accepted. Configured origin overrides forwarded headers and the build-time value. Leaving it unset retains the adapter's native fallback; Coast does not enable forwarded-header trust automatically.

[`check-bun-adapter.ts`](../../scripts/check-bun-adapter.ts) checks the exact dependency version, patch registration, patch bytes and installed handler/environment source before builds. Installed-source tests cover LAN HTTP, HTTPS, preserved request path/query, session-cookie security, cross-origin mutation rejection, runtime precedence, prefixing and invalid configuration. These are controlled request contracts, not actual-user/browser measurements. CI also checks same-origin and forged-origin POSTs against the final Linux container.

The new native timeout names are `CONNECTION_IDLE_TIMEOUT=60` and `SHUTDOWN_TIMEOUT=2`. The latter leaves room inside the existing supervisor's shutdown deadline. Body admission retains the adapter's existing 512 KiB default; no unrelated upload-limit increase is bundled into this migration.

## Native application changes

- Move Svelte configuration into Vite, retaining HTML preload hints without duplicate large Link response headers. Use Kit 3's generated tsconfig/types, `#lib` package imports and explicit `.js` import targets for TypeScript modules. Inventory tooling resolves those targets back to their actual source, including `.svelte.ts` owners.
- Treat page URLs and their search parameters as readonly; copy `.href` before mutation. Internal `goto` destinations retain existing route builders; external authentication/provider navigation remains a browser redirect. Onboarding's enhanced forms all use same-page named actions. Diagnostic 204 responses already have no body, and their transport does not parse a JSON result.
- Use native asynchronous shallow `goto`, `replace`, `reset:false` and `refreshAll`. Skip the previous full-route animation/dirty-form/menu side effects for shallow navigation, including Back/Forward. Detail navigation serializes its saved parent entry before its child and reads the last committed panel state. Its pending work is discarded after the browsing address or viewer changes. Navigation errors use existing action feedback.
- Preserve open overlays through shared refresh. Kit 3 deliberately separates refresh and navigation ownership: a refresh can finish while a pending navigation later completes. Do not restore Kit 2's shared invalidation token merely to satisfy old tests.
- Replace deprecated response helpers with native `Response.json`/`Response`. The broader Kit 3 error hook preserves safe app/framework/validation defaults; unexpected exceptions retain diagnostic logging and the generic public message.
- Regenerate the UI prop inventory; preserve all existing controls and visual treatment. No permissive development CORS configuration is added.

Historical audit source snapshots remain historical. The migration changes executable source/tooling/tests; it does not rewrite those old baselines to make them look current.

## Navigation repair and maintained proof

The Kit 2 patch cannot be applied or certified against Kit 3's changed owners. The new [Kit 3 patch](../../patches/sveltejs-kit-3.1.0.patch) checks ownership after asynchronous hooks and pending preload forks, discards obsolete forks, owns returned callbacks by unique token/wrapper, retires obsolete registrations, protects shallow state publication and preserves a newer navigation started during completion callbacks/store publication. It preserves Kit 3's independent refresh token.

The maintained fixture now extracts complete named functions using the TypeScript parser, rather than Kit 2 comment boundaries. It uses the installed real Svelte writable/tick/settled; render/load/history boundaries remain controlled. There are **18 Kit 3 schedules**: eight navigation/fork/callback schedules and ten refresh/shallow/cancellation/reentrancy schedules. This replaces the previous 21 Kit 2 schedules; the count change reflects framework semantics and owner boundaries, not 21 unchanged proofs. Stock-versus-patched outcomes are retained in the verification receipt. These schedules are not natural browser concurrency or latency measurements.

The build still refuses version, registration, patch or installed-source drift. Upgrade by reviewing the native owners, replaying stock-versus-candidate schedules, then running actual-data and authenticated browser acceptance. Never update hashes alone to bypass a failed proof. The old Kit 2 patch remains as historical evidence and is not registered or used.

## Local PostgreSQL test-host obstruction

The first maintained database-suite run reached the provider-sync deliberate-error test and timed out. Both local and selected shipping Bun reproduced it against the same existing test server. The PostgreSQL backends were sleeping in the ARM64 `write` syscall (64) to fd 2, the same full stderr pipe; subsequent fixture cleanup/retry statements waited on their locks. This is distinct from an app navigation or transaction-method regression. The six-test suite passes on selected shipping Bun with a fresh disposable PostgreSQL 17.11 instance using its standard file log collector. The full fresh-server run passes **657 tests across 79 suites, zero failures**. No app retry, SQL method, timeout increase or runtime rollback was introduced to conceal the obstruction. CI's PostgreSQL service checks remain independent.
