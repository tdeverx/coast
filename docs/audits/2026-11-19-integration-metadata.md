# Coast integration metadata audit

**Baseline** `1d53ea895` on main, 19 November 2026. This audit covers source data, persistence, conflict resolution and how catalogue facts reach discovery, details, tracking and playback. The priority settings below are a proposed contract.

## Findings

1. **Coast often throws away fields it has already fetched.** TMDB details request images, credits and release data, then persist a selected logo, bounded cast, taste features and a regional certificate. The lazy Insights read separately fetches status, networks, production companies, languages, dates and counts and turns them into display facts. Comic Vine creator roles and Open Library edition fields have similar short-lived paths. Keeping those already-observed facts offers immediate coverage without another request. [TMDB adapter](../../src/lib/providers/tmdb/adapter.server.ts#L182) · [TMDB Insights](../../src/lib/providers/tmdb/details.server.ts#L19) · [Reading import](../../src/lib/catalogue/reading.server.ts)
2. **Source selection is narrow and differs by consumer.** The screen resolver orders Jellyfin, TMDB and then the newest remaining provider. It resolves nine fields. The Library genre filter, effective release date and artwork selection apply their own rules. The `tmdb-only` selector filters provider snapshots but still allows the base `media` value, which can have been seeded from another source. Empty genre arrays are present values, so a higher-ranked empty array can also mask populated lower-ranked genres. [Resolver](../../src/lib/catalogue/metadata/resolve.ts) · [Screen artwork](../../src/lib/server/queries/media.ts#L405) · [Library predicate](../../src/lib/server/queries/library.ts#L74) · [Release selection](../../src/lib/catalogue/metadata/release-date.server.ts)
3. **Games, music and reading already share work identity, with different metadata ownership.** Screen has per-source, region- and language-aware snapshots. Games roll into `games` with IGDB features and variants. Music keeps per-server item and edition snapshots alongside shared artist, album and track records. Reading keeps a primary source on `reading_works`, merges subjects, and lets aliases fill only selected gaps. A source switch today cannot consistently rerank already-observed metadata across these families. [Catalogue schema](../../src/lib/server/db/schema.ts#L341) · [Game import](../../src/lib/core/games/service.server.ts) · [Music persistence](../../src/lib/music/persistence.server.ts) · [Reading import](../../src/lib/catalogue/reading.server.ts)
4. **Airtime and access need separate evidence.** The merged airtime job reads a bounded Trakt calendar window using app credentials. It stores known episode times and zoned series schedules, and matches existing identities. It will naturally miss episodes outside the window, unmatched shows and episodes absent from the local catalogue. Jellyfin can supply a series clock time without the zone required to schedule a specific episode. Film and TV release facts, request status and account-specific access therefore need distinct owners. [Airtime ingestion](../../src/lib/catalogue/air-schedule.server.ts) · [Jellyfin series DTO population](https://github.com/jellyfin/jellyfin/blob/master/Emby.Server.Implementations/Dto/DtoService.cs#L1448-L1455) · [Trakt calendar and timestamps](https://trakt.docs.apiary.io/reference/sync)

## Proposed source priority settings

Add **Metadata source priority** under the admin metadata settings. Offer **Balanced** and **Custom** presets as well as the existing local-preferred and TMDB-only screen choices. Start with one reorderable list per field family. In Custom, the administrator can move eligible providers up or down. Show each selected provider’s scope, a sample work’s winning field and its competing observed values, and why a source was skipped. Put per-server priority for two Jellyfin instances under the Jellyfin entry. Expose the effective winner and time in the existing metadata editor.

| Field family | Balanced order and conflict rule |
| --- | --- |
| Screen titles, plot, genres, identities and editorial structure | TMDB → Jellyfin → Trakt → legacy Coast fallback for descriptive facts. Prefer requested locale within a provider, then its original/default text. Use verified IDs and explicit relationship evidence to establish identity before metadata ranking. Conflicting identities require review. |
| Screen artwork | Personal preference where unlocked, then admin override/lock, then the authorized selected Jellyfin edition → TMDB artwork of the right language/type → other eligible providers. Keep usable alternatives for an artwork picker and source eligibility for every image. |
| Episode release schedule | Explicit admin correction first. Then a validated episode timestamp, a matching series time with a known time zone, and finally a date with the conservative elapsed-day rule. Within each precision choose Trakt → a verified local or licensed schedule source → dated catalogue observations as applicable. Scope availability and requests independently. |
| Movie releases and certifications | Exact region and requested release type first. TMDB → Trakt → Jellyfin for editorial release observations of equivalent precision. Age classification requires the correct region. A different market’s certificate remains labelled with its market. |
| Games | IGDB → Steam title/art hints for shared descriptive facts. Steam owns app/account ownership, playtime and unlocks. A configured Steam-only deployment keeps its imported title. |
| Music | Jellyfin for the user’s release and playable edition. A future verified MusicBrainz source can lead canonical recording/release identities and editorial credits. Keep release IDs, recording IDs and local file IDs distinct. |
| Books and comics | Open Library for book/work metadata and identified print editions. Comic Vine for an independently verified comic issue or volume, with Open Library as a verified cross-reference. Jellyfin owns the exact local reading-file link and its observed format. |
| Ratings, lists, access and request status | Keep provider ratings and counts as named measurements. Coast personal ratings, tracked history and saved intent stay with their existing sync contracts. The relevant authorized provider owns access or request evidence, including freshness and explicit withdrawal. |

Resolution should be deterministic within the same provider and precision. For each scalar choose a usable value by scope, configured order, observation freshness and stable source identity. Track unknown, explicit empty and withdrawn separately. For sets such as aliases, credits and links, combine by verified identity and role with provenance and preserve ordered member lists such as editions and episodes. Apply administrator overrides to shared facts, and user preferences to supported presentation fields. When a user selects TMDB-only, document and test whether pre-existing base rows are omitted or shown as labelled legacy fallback. [Current settings](../../src/routes/settings/[[section]]/+page.svelte#L1227) · [Current override editor](../../src/lib/catalogue/overrides/service.server.ts#L99)

## Implementation order

1. **Define the field contract and source evidence.** Record provider and instance, external entity, entity scope, language/region, source precision, source update time when supplied, Coast observation time, and whether the value is missing, present or withdrawn. Keep canonical work IDs and edition links. Preserve the existing screen snapshot shape where it fits and extend the existing medium stores once the required fields are concrete. Apply the same resolver semantics to indexed filters, cards, details and the editor.
2. **Retain useful fields that already arrive.** Start with TMDB and Trakt factual metadata, Comic Vine credited roles, already-loaded reading edition facts and Jellyfin local technical fields. Use a typed allowlist. Keep large asset lists, reviews and consent-sensitive account or social payloads in their existing lazy or scoped paths.
3. **Add source priority and verification.** Apply the preference to resolved reads and search/filter projections. Preview affected fields before publishing a revision. Test two Jellyfin instances, missing/empty/cleared values, exact-region ties, late refreshes, title locks and the provenance of selected artwork. Refresh derived indexes in bounded batches when a policy changes.
4. **Fill important fields upstream in bounded jobs.** Prioritise release/schedule timing, alternative titles/editions, credits, status and richer game release variants. Reuse existing jobs, request deduplication, paths and cache keys. Use explicit demand for provider offers, full artwork, reviews or rare edition lookups. Confirm attribution, storage and redistribution terms before making a new feed or field group permanently retained. [TMDB FAQ](https://developer.themoviedb.org/docs/faq) · [Open Library licensing](https://openlibrary.org/developers/licensing)
5. **Measure coverage and cost at each phase.** Report populated fields and disagreement rates by medium/source, scheduler call counts, before/after storage, filter equivalence, and p95 for rows and details. Preserve one bounded provider-free row read, visible-card hydration, job checkpoints and per-source rate limits. [Coast performance guidance](../performance.md#commands-provider-jobs-and-persistence)

## Evidence boundary

The merged code was compared with documented provider contracts. An aggregate-only, read-only live database sample found 331,025 TMDB, 38,582 Jellyfin and 106 Trakt screen snapshots. The sample held zero exact episode times and zero zoned series schedules, so it records live data coverage rather than the merged airtime capability. The same sample counted 299,466 episodes, 1,240 games, 51 comics and 1,109 music works. At that scale, enrich through bounded background jobs and read only the required fields on interactive paths.

## Implementation review

Admin Policies → Metadata can order Jellyfin, TMDB and Trakt independently for film and TV details, artwork and release evidence. The custom preset starts with TMDB for details, Jellyfin for artwork and Trakt for release evidence. Personal overrides and admin locks retain their precedence. Missing observations fall through to the next source and then to the saved catalogue value. Exact airtimes take precedence over day-only evidence, with source order deciding conflicts of equal precision. The existing metadata API gives the provider, source instance, observation time and locale for resolved fields. Jellyfin artwork still comes from the current viewer's authorized source inventory.

TMDB details now retain bounded production, audience, language, credit and episode facts. Jellyfin and Trakt snapshots retain available editorial facts, and Trakt's existing calendar job enriches matching titles and episodes. Reading imports retain verified Comic Vine roles and cover dates alongside Open Library language and a small edition sample. IGDB retains separate audience and critic measurements and a bounded set of release variants. These fields are filled on existing imports and refreshes. Provider-specific playback, request data and account activity keep their existing owners.

The performance pass checked card, summary, filter, episode and persistence boundaries. Source order changes resolve at read time without rewriting the catalogue, queuing a backfill or changing card-page size. Screen card queries still project only their needed snapshot columns. Reading and game card queries exclude the new facts, and stored comic credits can avoid a provider request. The Open Library edition sample comes from the existing exact indexed work request. Jellyfin's extra fields are limited to the catalogue job. Scheduled Trakt observations still use one calendar window, and identical observations skip writes. The migration adds two defaulted JSONB columns. PostgreSQL fixtures checked admin authorization, invalid orders, resolution parity and retained partial observations.

Detailed edition pages, additional aliases, broader music metadata and provider data still outside these projections stay in their existing owners. No production backfill, browser walkthrough or live latency comparison was run.
