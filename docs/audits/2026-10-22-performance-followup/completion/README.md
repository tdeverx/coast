## Bugs fixed and verified

1. **Library action navigation:** a Watch Load more response arriving while Listen navigation was entering could publish the old page and shallow-navigate back to Watch. Checking only the component props or committed route URL was too late. The existing Library owner now checks **pending navigation and committed pathname/query** before publishing a grid result or updating its retained-page URL. Embedded rows keep their existing scope. A changed grid URL invalidates its pending read; the viewer may retry after navigation settles. Two compiled-production-owner controls protect these separate boundaries. The [original real-response failure](receipts/browser-action-before.json) and [final replay](receipts/browser-action-after.json) show unchanged genuine Watch page-2 bytes released after choosing Listen; Listen retains 50 album cards.
2. **Preview background reselection:** Remove revoked the object URL but retained the file input's selection. Choosing the same image a second time did not dispatch change. Remove now also clears that input through its existing owner. The same actual JPEG, 3,053×4,320 and 1,956,330 bytes, decoded on three consecutive select/remove cycles; all three object URLs were revoked and none remained active. No layout, image transformation or new image-admission policy was introduced.

These are explicit remaining requirements, not passing checks. There is no blanket “audit complete” or “all performance risks resolved” status.
