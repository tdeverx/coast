# Frozen probes and safe reproduction

These `.txt` files are reviewed source transcripts from the disposable-copy audit, not application entry points. `<APP_ROOT>` and `<PRIVATE_RUN_ROOT>` replace the original absolute paths; [probe-pins](../probe-pins.json) records both original and transcript SHA256 values. The original scripts were bundled with existing host dependencies where necessary, then **executed with shipping Bun in the isolated Linux container**. Do not execute them unchanged against a development or live database.

For another run:

1. Follow the parent real-copy setup/cleanup protocol. Restore the same actual backup or identify a new data epoch. The completion run used a separate `coast_audit_completion_<32 hex>` database with comment `coast-performance-completion:<same hex>`. Every executable wrapper must verify **both** exact database name and comment before importing app modules or making writes. Some original transcripts rely on the outer verified wrapper; that is not permission to remove the guard in a new run.
2. Keep `{name, marker, url}` and copied encryption keys/session/media inputs in a mode-0700 private run directory. Pass database/credential variables before importing modules. Source files describe queries used to select actual inputs. Fail or report a gap when those inputs do not exist. Never manufacture catalogue rows, media bytes, accounts, provider replies or a naturally positive cohort.
3. Freeze source and dependency hashes. Adapt transcript paths in a private copy. Bundle through the existing host dependencies if the production image omits build-only `@sveltejs/kit`; record bundler runtime separately from the execution runtime. Do not install a production dependency to make an audit probe run.
4. Start the isolated production build on loopback 5175 with workers paused. `read-only-transport.ts.txt` allows only approved genuine provider GET/HEAD requests and caps admission at 3,000 per process. Keep native provider DNS pinning, TLS verification and allowlists authoritative. Public CDNs may rotate IPs between lookups: the corrected guard accepts a known approved HTTPS hostname only when native pinned transport supplies matching TLS serverName, certificate validation and `proxy:false`. Never loosen native transport checks or relabel a guard failure as an application failure.
5. Run each native family alone for attributable timings; run overlapping browser/probe work only for labelled contention observations. Repeated probes reuse controlled state unless freshly restored. Copy-only writes include sessions/tokens/shares, API enablement, three real native jobs, leases and failed-job controls, access observations, reader sessions, two temporary lists and one idle room. Preserve initial/final policy values, restore per-probe policy changes in `finally`, and retain failed attempts. The API enabled-policy epoch intentionally differs from the initial disabled-policy epoch.
6. HTTP probes hash complete responses and record status, headers, size, ordered totals and explicit policy outcomes. A 401 auth-envelope, successful empty array or disabled-feature 403 does not establish positive handler acceptance. The case-level matrix links exactly what ran. Review stateful GETs: source previews write copy-local preview receipts; music reads may persist access observations; room GET reconciles participants; enhanced metadata reads may write local metadata. Remote mutations remain denied.
7. For browser proof, use the maintained `scripts/performance-action-browser.js`, `performance-library-browser.js` and `performance-preview-browser.js`. Open an owned session on 5175 first. Each creates an independent context, avoiding CLI snapshots retaining the probe DOM. The action test changes **only the copied user's saved action**, obtains the real Watch page-2 body, holds delivery, switches through the actual menu to Listen, then releases that body unchanged. It must retain Listen and its album cards. Restore the saved action or destroy the copy afterwards.
8. For preview proof, copy the template to the private directory and replace its single `REPLACE_WITH_PRIVATE_REAL_IMAGE_PATH` sentinel with a JSON-escaped absolute path to an actual encoded image. Record its format/dimensions/byte size/hash privately; no generated bitmap is needed. Three selections of the **same** file must decode, Remove must clear input.files, and all object URLs must be revoked. This is lifetime/behavior acceptance, not a decoded/GPU image limit.
9. Reader reproduction also uses the existing `scripts/reading-delivery-verification.ts` with actual retained CBR/CBZ paths. Preserve every-page independent byte equality, cold preparation, cancellation/draining, warm/shared leases, budget and orphan checks. Parent RSS excludes native children/browser; don't add them without a process-tree measurement. The actual crop harness must link baseline/current controllers, preserve FFmpeg arguments, feed genuine accessible video sources and compare rectangles; serial baseline vs parallel current is **not** a speedup trial. Direct request context is not hosted Jellyfin authorization acceptance.
10. Save safe structured results, source/command order and failures before cleanup. Do not commit raw SQL plans/parameters, private DTOs/IDs, cookies, tokens, media URLs, DOM/heap snapshots or actual content. Verify zero clients, exact name/comment, then drop only the owned copy. Stop its app/proxy/helpers/PostgreSQL/container, delete private credential inputs and verify unrelated user edits. A cleanup receipt is required, not implied by process exit.

A protocol, source transcript or guarded skip is never a passing result. Repeating only supplementary fixtures does not refresh actual-data acceptance. Missing formats, natural provider cohorts, hosted authorization, physical devices and contract decisions stay listed in the completion report.
