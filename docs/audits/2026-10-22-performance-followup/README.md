## Adopted contracts

- **Queue/Continue:** queue edits acquire the existing feature-policy fence and user advisory lock in the same order as Continue/tracking. A later queue addition waits for removal and survives Undo with its exact timestamp. No second scheduler or new lock namespace is introduced.
- **Jellyfin:** the account row uses `FOR NO KEY UPDATE`, preserving generation/reset protection while allowing a writer's foreign-key key-share lock. Finalization selects at most **100 source rows or intents per transaction**, bulk seeds missing intents, then enqueues current versions. Its keyset cursor and effects commit in the same transaction. Existing five-boundary/ten-second job yielding stays authoritative; retry resumes rather than walking the entire history again. No network I/O belongs inside the transaction.
- **Eligibility:** non-screen Recently added and action-scoped Progress omit the unrelated episode-grant expansion. Direct root/descendant availability still requires the viewer's connected, enabled source. Mixed/default and Watch semantics remain unchanged.
- **Finished/Dropped:** the shared Collection CTE accepts a status-only projection, allowing PostgreSQL to prune unused materialized assessment work. Full Collection consumers keep the default complete projection. No global `work_mem` or JIT change is used to mask spills.
- **SQL cancellation:** only explicitly read-only Progress, Recently added, Watch Library and Collection owners opt in. One abort listener tracks their native lazy query handles, including transaction callbacks; cancellation never targets a pooled backend PID. Native JSON, prepared statements and `values()` remain intact. Acknowledged mutations and provider observation writes are not globally cancelled by HTTP disconnects.
- **Provider admission:** the existing shared lane admits work with a separate **60-second queue-wait bound**, configurable through internal `queueTimeoutMs`. Admission clears that timer. Upstream timeout/pacing and long-lived stream behavior remain separate. Expiry is a local capacity error, not evidence that a provider rejected the operation.
- **Images:** the existing shared action continues to own viewport/rail demand. Destruction removes observers/listeners/queued work and resets the disposed image to a valid inline pixel after clearing `srcset`. An empty image candidate retained native viewport listeners in the measured Chromium build, including images that never intersected. Disposal changes no active artwork, resolution, ordering or approved layout. The [Blink source](https://chromium.googlesource.com/chromium/src/+/HEAD/third_party/blink/renderer/core/html/html_image_element.cc#293) explains the matching candidate/listener relationship; the real-app heap experiment is the acceptance evidence, not that source reference alone. The attempted native-eager change did not fix retention and was reverted.
- **Watch Library controls:** ordinary Watch Library already requires a permitted source. Hide its redundant Available only toggle; keep it for Collection and actions where it changes membership. Do not substitute all catalogue movies for the authorized Library count.
- **Companion:** one credential/source-scoped owner admits at most **64** running/queued/completed crop entries, **two** FFmpeg children, and expires unused completed entries after **15 minutes**, checked on admission. A cancelled consumer releases only its lease; the final consumer cancels, kills/drains the child and releases its slot. Timeout includes queue admission and analysis, bounded at **20 seconds**. Retain only the final **65,536 characters** of stderr while draining it. Current and baseline rectangles match on two actual videos; this does not establish every codec, hardware or hosted authorization case.

## Required regression gates

Run focused controls while editing; once final source is stable, run the relevant full batch:

```sh
# Exact pinned Bun in CI/container; label any supplementary host runtime separately.
bun run test
bun run check
bun run build
bun run code:inventory
bun run ui:inventory:check
bun run code:style

# Creates/drops its own authored CI databases; never benchmarks the supplied DB.
bun run test:db jellyfin-finalization-db.test.ts jellyfin-reconciliation-db.test.ts jellyfin-recovery-db.test.ts collection-db.test.ts domain-db.test.ts
```

The copy-guard test rejects ordinary/unmarked databases before connecting. The register test checks executable owner/test references, package/Docker/CI runtime pin consistency and frozen owner hashes. An owner change fails until the affected acceptance, evidence epoch and remaining scope are explicitly reviewed and refreshed; do not mechanically update hashes to reuse stale measurements. The native scripts emit runtime/revision, executable hash, source reference, explicit pass/failure and controlled-state counts. A source hash identifies an evidence epoch; it is not a replacement for behavior or performance tests. Native actual-data acceptance and authored database/DOM/process fixtures remain different evidence classes. A guarded skip, empty response or stale log is never a pass; clear attempt-specific stdout/stderr files before rerunning and keep the earlier failed receipt.

When changing any registered owner, review its contract, run the corresponding regressions and refresh actual evidence where membership, privacy, locks, source generations or resource lifetime can change. Update the register, verification and exact remaining cases in the same change. Changes to workload, policy, generated output, dataset or environment require a new comparison identity; existing administrator benchmark comparison guards must continue to refuse incompatible histories. Do not add arbitrary millisecond thresholds, blanket memory/connection expiry or a new architecture based solely on a local microbenchmark.
