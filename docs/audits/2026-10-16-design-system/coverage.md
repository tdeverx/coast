# Source coverage ledger

16 October 2026. Companion to the [consolidated audit](README.md).

This ledger accounts for every `.svelte` source file at the audited snapshot. Static instantiations were collected with the Svelte parser; area reports provide manual template/state evidence. Review owner assigns the primary report and does not exclude cross-review. FND = foundations/reference, CAT = catalogue/media, SOC = social/playback, ADM = account/admin.

**This is not a runtime-certified state matrix.** A registered recipe means the current inventory has an example by that name, not that all its states work or are isolated. Static child names below include feature-owned/dynamically resolved names; an unresolved static edge is not evidence of unmapped UI. Routes are compositions, not missing reusable primitives. Native styled elements and format renderers are legitimate owners.

Scope is 118 files: 63 registered components, 30 non-preview routes, 19 other library files, 6 preview files. The four chart internals and material editor already have dedicated reference sections. Supporting TypeScript/CSS files are described in independent reports, not counted as additional Svelte surfaces.

## Dynamic and non-Svelte rendering declarations to retain

- Root layout lazily instantiates Reader, MediaModal, NotificationInbox, FriendsPanel and StreamsPanel. These need explicit inventory edges to their existing domain owners, not eager imports.
- For You lazily instantiates DynamicFeed, which composes the existing Shelf renderer. Do not replace its feature-owned append/admission logic with a reference loader.
- ChartView selects chart renderers; ChartMark is an SVG interaction target, not an ordinary action button. Dedicated chart exploration already exists.
- Playback creates video/audio/crop-canvas targets; reading engines create PDF canvas, EPUB documents and comic image targets. These are format/engine internals, not competing element systems. Selected-format-only loading must remain.
- Materials create SVG/noise layers, and segmented controls create a sliding pill. Their imperative DOM is an implementation of existing elements. No material rewrite is part of this audit.
- Shared `.field`, `.check`, `.notice`, `.badge`, `.table`, `.overflow`, `.panel`, `.skeleton` and auth layout styles are existing native design patterns. Add reference recipes before considering wrappers.

For actual state lists and acceptance requirements, use the linked reports and the stage-2 reference families in the consolidated audit. The ledger is a coverage index, not a second work list.
