## Actual-data method

Two disposable PostgreSQL databases are exact TEMPLATE copies of the retained real catalogue. Both enforce read-only; both use the same older retained object epoch, before 0064 deletion-cleanup adoption. This compares application reads on matched data/schema, not a full deployment/migration replay. Actual admin and catalogue IDs/title are admitted once and retained privately. Selected natural cohorts include829 episodes in the largest season,23 collection relationships,32 album containment edges and651 game achievements. The local header owners do not claim to load every child/achievement.

Thirteen native owners run in eight fresh processes/four alternating pairs (AB,BA,AB,BA):104 executions and52 paired output comparisons. **All 13 complete ordered canonical outputs are identical across all eight runs**, including IDs/dates/values. Only JSON object key ordering is canonicalized. There are zero write admissions and zero fetch attempts. Both owned copies are dropped/absence confirmed; private runtime files are removed. The original actual clone matches all 102 tables / 1,864,145 rows and its canonical logical digest after execution.

Bun 1.4.3 and identical native limit 10 read-only pools are used. The same wrapper records query admissions/counters, elapsed time, process CPU and RSS for both variants. Pool bootstrap/shutdown, HTTP/authentication, actual rendering, media decode and providers are excluded. Counts below are ORM logger statements; raw tagged admissions are separate and unchanged in these cases. Raw unsafe overlaps ORM and must not be added to it.
