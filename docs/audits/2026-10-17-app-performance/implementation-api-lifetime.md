# Shared API cancellation and global side effects

The common `requestApi` owner now checks its caller signal before transport admission, after transport completion, and after JSON settlement. A JSON `AbortError` is preserved even without a supplied signal. Malformed successful JSON now rejects as a protocol error instead of returning an error-shaped object as a successful typed result. Invalid error-response JSON retains its HTTP failure and safe fallback; a null error payload no longer throws a payload TypeError. Genuine non-shared401responses still publish authentication expiry, and shared-playback401responses remain excluded from that global event.

This closes a source-confirmed lifetime gap: an aborted request whose transport completes late, or whose body abort was converted into an error-shaped payload, could otherwise publish a false global expiry into the current viewer. The same entry fence prevents an already-cancelled request from admitting a transport, and the post-transport fence prevents late diagnostic-level publication. Valid JSON command acknowledgements retain their existing behavior. Cancellation does not undo an already-committed server write or cancel admitted SQL.

The shared owner serves ordinary API, injected preview clients and captured playback authority; cards, menus, dialogs, polls and reader/player consumers all inherit its behavior. No per-feature wrapper, dependency or visual change was added.

Ten focused tests /38assertions pass in the current client suite. New controlled fault cases cover abort-ignoring transport, body cancellation with and without a supplied signal, zero transport admission after prior cancellation, genuine expiry and shared-playback exclusion, malformed success preventing a false acknowledgement/refresh, and invalid/null error bodies preserving HTTP status. Valid JSON null remains accepted. Existing relationship delivery, refresh acknowledgement and captured authority regressions remain. These are protocol/lifecycle fault proofs with controlled responses, not actual-data performance measurements. A natural actual two-viewer late401schedule remains unobserved. Actual signed-in and anonymous demand acceptance elsewhere in this audit is separate evidence.

[Focused results](evidence/implementation-api-lifetime-tests.txt). Preserve these ownership boundaries whenever response parsing or global error delivery changes; do not turn body cancellation into a generic server error before checking its owner.

A protocol failure after a server write can still have an unknown outcome, as with a lost network response; this change does not promise command idempotence. The staged toast candidate separately reconciles its unavailable persistent retry.
