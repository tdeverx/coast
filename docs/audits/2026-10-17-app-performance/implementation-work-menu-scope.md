# Shared menu scope serialization — HELPER-01 / UIC-01

The shared `workMenuScope` owner omits only `user.settings.profile.avatar` from its internal invalidation key. Independent source review confirmed that the five fetched menu consumer families do not use the actor avatar: screen action data, shared work actions, music identity, list picker and party saved-music queue picker. Social actor avatars and visible avatar rendering remain separate. Every other settings value and every existing viewer, role, tracking revision, occurrence, feature, experiment and capability dependency remains in the key.

[Machine receipt](implementation-work-menu-scope.json), [actual saved settings](evidence/implementation-work-menu-scope-actual.json), [focused regressions](evidence/implementation-work-menu-scope-tests.txt), [portable actual probe](probes/work-menu-scope-real.ts).

Sixteen complete parsed-key comparisons used four actual enabled accounts, saved catalogue IDs in four categories, current feature config and production content revisions. Three accounts have inline avatars. The tested largest key fell from **16,640 to 1,385 bytes**. Every value outside the intentionally omitted avatar matched the immutable baseline. Equivalent session replacement and avatar removal within the existing profile preserve the key. No raw settings, avatar bytes, identifiers or keys were saved.

These are internal string bytes, not network payload savings or measured CPU/heap/latency. The original avatar string remains owned by the session for display. Other settings still serialize per consumer, and the small object projection allocates per call; there is no new global cache or retained owner. Adding/removing the profile object can still conservatively invalidate the menu. Missing saved list/party cohorts were not manufactured.

Three new authored tests use the actual production scope function and compiled menu resource to verify unchanged-session reuse, retained policy/presentation/identity invalidation and safe pending-read handling across avatar versus role changes. With eleven existing owner tests, **14 tests / 59 assertions pass**. A full check caught one missing test callback annotation; the corrected test is explicitly typed, and the failed preflight is retained. Common gates and current normal-dev acceptance are recorded by the coordinator.

A larger minimal policy key computed once per client remains an option. It requires an explicit full dependency contract and SSR/preview/viewer isolation review; this change deliberately retains the remaining conservative dependencies. Future drift should rerun the actual-settings comparison, audit new menu DTO dependencies before adding actor-avatar fields, and retain the controller regressions. Rollback is this small projection and its test only; no schema, data or dependency action is required.
