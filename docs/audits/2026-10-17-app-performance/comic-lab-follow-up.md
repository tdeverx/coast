## Healthy ownership already present

| Owner | Source-confirmed behavior |
| --- | --- |
| Isolation/build | Own exact dependency manifest/lock, local process and split dynamic engine imports; no Coast imports/config/database/progress writes. Build output is ignored. Only the selected engine is requested/mounted. Fiber deliberately shares the Three paper model rather than pretending to be an independent graphics engine. |
| Local server | Loopback bind;16KiB streamed request-body bound; finite60-book upstream pages; redirect rejection;30s upstream request signal combined with client-disconnect cancellation; streamed download backpressure and128MiB byte cap. Realpath containment protects static file selection. |
| Archive |128MiB compressed/512MiB declared expanded/32MiB per-page/10,000-entry admission. Lazy extraction, serialized decompression, actual output-byte checks, strict/CRC options, raster signatures, path/duplicate/encryption checks. Close aborts queued work, clears entry references, waits for extraction and closes the ZIP reader. |
| App/document | Selection/request signals and generation fences prevent stale publication. Document replacement disposes the previous renderer, aborts page work, clears cached canvases and closes the archive. Library replacement aborts the older read. Decoded bitmaps close in `finally`. |
| Engines | All expose `dispose`; observers/listeners and textures/scene/context resources have ordinary teardown. Rendering is demand/animation driven, not a permanent idle render loop. Three/Fiber cap pixel ratio at2 and prune page textures; Babylon prunes pending textures and cancels animation ownership; CSS tracks/cancels its animations and clears image sources. |

These mechanisms are useful defenses, not proof of low CPU/RSS, leak freedom or real-format compatibility.

## Source observations and options

| Separate observation | Mechanism, owner and path forward |

| **COMIC-LAB-OBS-01 — CPU and decoded-image admission** | [Archive:76–79,160–176 (separate experiment)](publication.md#excluded-experiment) explicitly disables ZIP Web Workers, leaving the page-side orchestration/JavaScript fallback without that isolation. Browser-native codec scheduling was not inspected or measured. Serial extraction bounds concurrency, not per-page CPU. [App:29–37 (separate experiment)](publication.md#excluded-experiment) checks100million pixels **after** `createImageBitmap`, then downsamples to2048 on the longest edge. A100MP RGBA8 surface is about400MB arithmetically, before canvas/GPU copies; this is not a measured browser allocation. CSS additionally runs synchronous PNG `toDataURL` on requested/revisited pages (`captured css.js:106–110,310`). **Shared owner:** archive/page-asset admission serving local/Jellyfin archives and all four engines/Flat. First trace actual accepted pages and choose an explicit decoded-byte/work policy; then consider dimension preflight, the existing ZIP worker support, and one owned encoded-page cache if repeated encoding dominates. Preserve exact page order/quality and cancellation; do not silently pick a lower image budget or replace the prototype's visuals. |
| **COMIC-LAB-OBS-02 — factory failure lacks complete construction ownership** | [App:78–95 (separate experiment)](publication.md#excluded-experiment) receives a disposable handle only after `createRenderer` resolves. [Three:20–32,88–96 (separate experiment)](publication.md#excluded-experiment) allocates scene/page resources across awaits; `captured fiber.js:10–25` allocates canvas/WebGL/root before awaiting configuration, without a failure `finally`. A rejected configuration or constructor path can bypass the completed handle's cleanup. Retained GPU resources or a natural failure were **not** demonstrated. **Shared owner:** the factory contract and app sequence boundary, across Three/Fiber/Babylon/CSS. Adopt an explicit cancellable construction lifetime with cleanup on rejection and late completion; retain CSS's existing failure-dispose pattern. Verify held page decode/configuration, initialization failure, engine/document replacement and context loss before claiming a leak fix. |
| **COMIC-LAB-OBS-03 — Flat still drives the hidden renderer** | [App:175–181 (separate experiment)](publication.md#excluded-experiment) keeps the 3D renderer alive behind `visibility:hidden`; open/turn dispatch still calls its methods. Thus Flat can retain both GPU page assets and copied flat canvases and execute hidden Three/Fiber/Babylon/CSS turns. Sources request680–800ms animation durations, subject to reduced motion and frame scheduling; this is not a measured visible delay. **Shared owner:** app reading-state/view ownership and the common renderer interface. Measure actual Flat turns, then decide whether preserving an immediately reusable 3D scene is worth its memory or whether Flat should suspend/release it and update page state without hidden animation. That decision affects interaction behavior and needs an explicit design choice. |
| **COMIC-LAB-OBS-04 — one shelf action can scan many pages and retain every card** | [Server:214–230 (separate experiment)](publication.md#excluded-experiment) fetches60 `Book` items and filters CBZ/ZIP afterward. [App:149–166 (separate experiment)](publication.md#excluded-experiment) automatically continues while a page contains no supported comic. An all-unsupported library can therefore trigger many sequential calls until completion or the server's60,000 start-index ceiling; it is not one60-item unit of admitted work. Repeated Load more appends all matching buttons/cover elements until reset/logout. Each requested cover performs an authoritative item read and then image fetch ([server:237–248 (separate experiment)](publication.md#excluded-experiment)); lazy images limit initial demand, not eventual fanout or retained DOM. **Shared owner:** library traversal/presentation and scoped media-access owner. Bound scans per interaction with a resumable next offset and snapshot the search term for that traversal; measure real library density before choosing DOM windowing or session-scoped cover/access coalescing. Preserve permissions, ordering and unsupported-format filtering. No actual large library or cover request count was observed. |
| **COMIC-LAB-OBS-05 — server limits/caching leave avoidable materialization** | [Server:116–122 (separate experiment)](publication.md#excluded-experiment) reads the entire upstream JSON text before enforcing4MiB. [Static:141–148 (separate experiment)](publication.md#excluded-experiment) reads the whole file even for HEAD, and serves every asset `no-store`. **Shared owner:** server upstream/static IO, affecting login/library/item metadata and every shell/engine/vendor/image asset. | **COMIC-LAB-OBS-06 — cached-page restoration is unverified** | [App:187 (separate experiment)](publication.md#excluded-experiment) always disposes renderer/document and aborts controllers on `pagehide`, with no `pageshow` reinitialization. **Conditional source hypothesis:** if a browser restores this same document from its back/forward cache, it could restore controls referring to closed resources. Actual cache eligibility/restoration was not tested. **Shared owner:** document/renderer page lifetime across all engines and Flat. Test an actual persisted round trip before choosing `pagehide.persisted` suspension versus explicit `pageshow` reconstruction; preserve permanent-close cleanup. |

Smaller costs remain visible without being promoted to incidents: the sample atlas is a fixed1024×1536 bitmap retained for reuse (3,604,114 compressed bytes, about6MiB RGBA8 arithmetic); page-cache entry count is not a combined canvas/GPU/encoded-byte budget; and server sessions expire after8hours but have no entry cap and are swept on requests ([server:91–92,170 (separate experiment)](publication.md#excluded-experiment)). Re-login/expiry deletes local session entries without a general per-session in-flight abort owner; logout revocation is explicitly best effort. Measure actual demand before adding retention/resource policy.

## Verification boundary and next acceptance

The two test sources define **eight archive tests and one local fake-Jellyfin test**. Archive cases build their own ZIPs around a tiny PNG and controlled header mutations; they protect natural ordering, byte/path limits, malformed containers, queue cancellation and close contracts. The server test uses invented users/items, a fake upstream and strings such as `ZIP-DATA`/`cover`; it verifies proxy/session/pagination/range behavior, not decoding a real downloaded comic. The README's separate four-page fixture/browser claim is not linked to an independently retained real-account corpus here.

Before moving any engine into Coast, capture an authorized actual CBZ/ZIP cohort with real JPEG/PNG/WebP/GIF/AVIF pages where available, missing/corrupt/oversized real-file cases and long mixed-format libraries. Keep absent formats explicit. Run the same page identities, proportions and turns through Three, shared-model Fiber, Babylon, CSS and Flat; record initial/turn work, main-thread long tasks, decoded/canvas/GPU memory, repeated switch/close cycles, mid-enumeration/in-progress extraction abort, context loss and persisted page restoration. Separate live-provider/download evidence from retained-file replay and authored failure tests. CBR/RAR/PDF/EPUB are intentionally unsupported here; Coast's earlier CBR evidence does not certify this independent ZIP pipeline.

Maintain this experiment's own source manifest and actual-corpus receipts if it is retained. Its dependency versions, rendering-quality differences, engine/module-cache lifetimes and build outputs should be pinned alongside any comparison. Keep these observations outside the94 baseline register until a deliberate integration decision supplies canonical ownership and acceptance.
