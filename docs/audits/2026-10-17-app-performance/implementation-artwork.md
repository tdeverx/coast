# PJ-01 artwork request lifetime implementation

The shared lifecycle now belongs to `src/lib/providers/artwork-flight.server.ts`. Both the public TMDB cache and authenticated server-artwork cache use it. The existing TMDB waiter/controller logic was extracted; the generic provider single-flight and queue owners were not changed.

Each caller owns an independent cancellable wait. A flight owns its own upstream controller, and aborts it only when its final interested caller leaves. The abandoned map entry is removed immediately so retry can start; active work retains its slot until the producer actually settles. Completion removes only the same entry, so an old cancelled download cannot evict its replacement. Results and failures are not cached by this owner.

`serverArtwork` now requires a caller signal and supplies the owned upstream signal to its download callback. Both actual consumers pass those signals through their existing transport: `providers/artwork.server.ts` covers private screen/reading artwork and `music/artwork.server.ts` covers private music artwork. Their current authorization/access checks, account-generation scope, formats, byte limits and fallback behavior remain in their existing owners. Private artwork caching disabled still means independent caller-owned requests. Public TMDB retains its existing four-active-download rule and CDN fallback, including slot retention while cancelled work settles. This change selects no new aggregate resource budget.

Abort checks run before cache work/join, after asynchronous reads, after response/body delivery, before optional persistence admission, and before returning an image. A caller cancellation cannot retract a disk write which was already admitted; the implementation prevents new admission after cancellation is observed. Optional disk-cache admission decline still delivers a valid image. Existing cache failures and invalid-image responses retain their prior error/fallback contracts.

These controlled correctness tests exercise actual compiled owners with bounded inert transport/cache boundaries: leader and joining cancellation, a remaining viewer, final cancellation, cancelled cache reads, cancellation during persistence-policy refresh, old completion versus replacement, cache-disabled independence, optional persistence decline, existing TMDB four-slot accounting, and cancellation through actual adapter/queue functions. Their tiny image fixtures are not actual-data performance measurements.

The final-source [`evidence/implementation-artwork-real-cache-final.json`](evidence/implementation-artwork-real-cache-final.json) is a separate actual-data proof from [`probes/real-artwork-flight.ts`](probes/real-artwork-flight.ts). It pins six current production source files and verifies those hashes remain unchanged throughout the run. The public case matches an existing actual catalogue poster/backdrop to an existing normal-dev TMDB cache file, using the current cache identity algorithm. The selected JPEG contains **242,684 actual bytes**. The original owner reads a private staging copy through the real filesystem cache and returns identical bytes without a provider request. The shared current TMDB owner then passes a controlled replay using those actual bytes: one upstream for two viewers, independently cancelled leader, surviving follower, final-consumer abort, safe retry/replacement, and subsequent real filesystem cache hit.

The initial local cache inventory had zero private server images, so public JPEG evidence was not substituted for private WebP. The root browser pass subsequently captured the response of the same displayed private artwork image in the signed-in normal-dev Library using the browser's existing `downloadMedia` capability. It observed `complete=true` and `naturalWidth=780`. The private response has **58,904 bytes**, verified RIFF/WEBP magic and SHA-256 `e7f2f5b8525dbe447bde5721a1915bbbc75e7c6a52432538ab15fd43567be58f`. The image and its source URL remain in private temporary files; neither image nor raw private source IDs are committed. The probe resolves that source in memory against existing available media, an active account and current generation, then reconstructs the production private cache scope without extracting credentials.

Using those actual private bytes, the exact audited `serverArtwork` source reproduces the defect: leader cancellation rejects both same-key callers while the follower's request remains un-aborted. The current private owner passes independent leader/joining cancellation, a surviving viewer receiving identical WebP, real filesystem persistence/hit, final-consumer upstream abort, no persistence of a late abandoned result, safe retry/replacement, and independent requests when private caching is disabled. **All29 combined actual-data checks pass; zero external provider calls, database writes or credential extraction.** Only private staging directories are written; original normal-dev cache files and settings are unchanged.

A later replay reran the unchanged probe against the final frozen production source after the separate shared cache recovery implementation. All **29 checks pass again**, with six source pins matching the final files and zero external calls. The initial receipt remains byte-for-byte in [implementation-artwork-real-cache-prior.json](evidence/implementation-artwork-real-cache-prior.json), and its original filename is also preserved; its older hashes have not been relabelled as final-source evidence. The machine receipt records both artifact hashes and the final pins. This is additional lifecycle/cache-hit evidence on final source, not a new natural-corruption or latency observation. The runner's `PGOPTIONS` setting does **not** establish a universal statement timeout: this probe makes no such per-query/connection assertion.

The probe waits for observed viewer joins before cancellation. Current joins are observed through caller abort-listener registration; an observation counter in the loaded audited copy records the point before awaiting its existing shared promise. This avoids assuming that the first download start means a filesystem-delayed follower has already joined. The observations change no production state logic.

These proof levels are intentionally distinct. The browser observation proves authorized display and response bytes. Filesystem cases prove cache persistence/hits. Replay controls upstream timing and proves ownership/cancellation behavior on actual bytes and scope; it does not demonstrate natural concurrent-provider timing, production cancellation frequency, or a measured user-facing speedup. Concurrent live requests, authorization/account replacement and broader normal-dev navigation remain separate acceptance schedules.

## Separate cache recovery, implemented later

The historical source observation was that invalid private cache bytes could trigger repeated downloads while immutable `put` retained the indexed bad entry; TMDB could instead return 502 without trying replacement. This was separate from PJ-01's lifecycle repair and original passing receipt.

The later [shared cache recovery implementation](implementation-artwork-cache-recovery.md) now validates inside the serialized cache read, evicts rejected bytes and index together, and lets both consumers persist a valid replacement. Its own 20-test / 115-assertion suite and 28-check controlled actual JPEG/WebP fault proof cover replacement, retention, accounting and validator exceptions. That fault proof uses disposable truncated copies and establishes no natural corrupt-cache incidence. Existing magic-header checks can still accept header-preserving decode corruption; no new decoder policy was added. The PJ-01 final-source replay above verifies that the lifetime contracts remain intact after this separate change.

## Consumer and drift boundary

Production consumers are the private screen/reading relay, private music relay, and public TMDB relay reached by both guest public browsing and authenticated artwork routes. Every caller was searched again, including direct server-artwork tests. The shared fixture matrix must continue to run for both cache owners when transport, persistence, cancellation or slot policy changes. No UI design, API response headers, credentials, provider writes, schema, indexes or dependencies were changed. Broader crop budgets (PJ-02/03), provider wait deadlines and private aggregate-flight limits require their own reviewed policy; this lifetime repair does not silently choose them.
