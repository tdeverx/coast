# UIS-05: compact empty charts do not request a renderer

17 October 2026. Changed only the shared `src/lib/ui/charts/ChartView.svelte` load-error effect. It now clears prior error state and returns for a compact model with no rows before reading the lazy renderer derived value. Existing compact-empty text, populated charts, noncompact-empty charts, captions, selection and standard/extended Promise reuse are unchanged. Source SHA-256: `6fe91873da7be529bafb7d19ad0238708055b034e2cb72067c9aaf7604ccdb50`.

The canonical owner serves DetailCard insight charts, game/reading progress and the chart gallery. The change avoids initial engine demand for the existing compact-empty branch. If a previously demanded import rejects after the chart becomes empty or is disposed, its old error callback cannot publish feedback; current populated-chart import failures keep their existing message. An import already started cannot be cancelled, and its module can remain in the browser's normal module cache. This is not a bundle-size or repeated network-transfer claim.

The installed Svelte compiler was checked before choosing the fix. Server output uses `const loaded = $.derived(() => renderer(model.styleId))`, and the installed server `derived` helper defers the function until read. The compact-empty SSR branch never calls `loaded()`. SSR was therefore already healthy; the unnecessary demand came from the client's effect. A nullable promise or markup change was unnecessary.

Verification: **5 passing tests, 37 assertions** across `tests/chart-view-demand.test.ts` and `tests/chart-presentation.test.ts`, Bun 1.4.3. The new regressions execute the production script compiled with Svelte's client runtime and the production template compiled/rendered with the actual server compiler/runtime. Only renderer transport and application feedback/context boundaries are isolated. They check empty/populated transitions, style changes, cached Promise reuse, current versus late failure delivery, disposal, compact-empty SSR text with zero engine requests, and preserved noncompact-empty/populated SSR demand. These are lifecycle/compilation proofs with authored test models, not actual-user chart performance measurements. Raw output: [implementation-chart-demand-tests.txt](evidence/implementation-chart-demand-tests.txt).

Actual signed-in empty-chart import/network acceptance has not been separately executed. No new actual-data capture was made for this change and no latency/heap saving is claimed. Future acceptance should open an actual empty insight card from a cold browser module cache, then populate it or switch scope and verify one renderer demand, correct chart text and no stale failure. Keep the installed-compiler SSR regression when upgrading Svelte so eager lowering cannot silently restore this edge.
