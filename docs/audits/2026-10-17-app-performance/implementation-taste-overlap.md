# MIN-08: bounded feature overlap lookup

17 October 2026. Implemented only in `src/lib/social/taste.ts`, the pure owner used by `friendInsights` and its social taste comparison consumers. No schema, provider call, dependency, cache, account policy or UI behavior changed. Source SHA-256: `c539c8aeb136337eed720218bec9e908e63a14ff64fbf58ee5d055efdb23f7ca`.

Each feature dimension now builds the right-hand value Map once, reuses it for the existing cosine calculation, and counts left affinities with `Map.has`. IDs are primitive strings. Right duplicate IDs retain the same last-value Map semantics as the original cosine calculation; counting still visits every left affinity, preserving left duplicate counts and order. Positive-affinity/cast thresholds, score qualification, weights and blend order are unchanged. There is no global or cross-user retained index.

`buildTasteProfile` caps each dimension at 500 affinities. The previous nested membership scan could test 500×500 ID equalities per dimension; the indexed owner performs at most 500 insertions plus 500 membership lookups. These are different operation types, not equivalent CPU instructions. Map construction has a cost for small or empty cohorts; this establishes a linear bound and shared ownership, not a speedup for every comparison.

## Actual data verification

The read-only private-clone probe extracted the current insights evidence SQL and used its existing meaningful-evidence sample of up to 300 rows per user. It hydrated only existing persisted work features, then compared the complete pure result from audited baseline, instrumented current and unmodified current implementations in memory. No feature IDs/names, work IDs/titles, users, scores or raw preference payloads were retained. No catalogue/features/settings were fabricated; no account/policy lock or data write was used.

**40 completed comparisons across 10 owner/viewer contexts matched completely**, and all operation bounds held. Fifteen medium cohorts had works on both sides. The completed corpus covered three left-side owners and four right-side owners; actual affinity lengths reached 243 on the left and the real 500 cap on the right. Across this completed corpus, the changed overlap operation counts were 236,666 baseline equality tests versus 4,114 index insertions and 3,152 membership lookups. Sixteen cohorts required more counted index operations than baseline equalities, illustrating the small/empty-cohort construction tradeoff; these counts do not establish a latency regression or improvement.

The planned capture was larger: 64 comparisons across 16 contexts. It was **intentionally cancelled during a later existing insights SELECT** after a sufficient safe corpus had completed. The runner exited **1**, the PostgreSQL cancellation error is retained, and the incomplete capture is not represented as a successful full run. Application source stayed unchanged throughout. Only completed comparisons support the equivalence result. Themes, developers, publishers, mechanics and perspectives had no eligible positive affinities on both sides in that corpus; no data was invented to fill those gaps.
