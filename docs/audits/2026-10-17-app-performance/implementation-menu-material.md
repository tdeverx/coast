# Open menu material ownership

The shared Button menu surface now creates its existing glass action only while that menu is open. This implements a narrow resource-ownership slice of `UIS-04`, using Button's existing `surfaceMaterial` action. All menu components, controllers, drafts and domain command owners retain their existing lifetimes. The broader card activation and Shelf retention findings remain open. [Machine-readable report and pins](implementation-menu-material.json).

## Exact change and consumers

The only application edit is [Button's menu surface binding](/Users/admin/Documents/ChatGPT/coast-new/src/lib/ui/components/Button.svelte:100): `use:liquidGlass={{variant:'glassDark'}}` becomes `use:surfaceMaterial={{enabled:controller.open,variant:'glassDark',blur:false}}`. The existing action at lines52–64 already owns creation, keyed updates and destruction of the real glass action for ordinary controls. Its behavior is reused without a new helper, dependency, renderer, policy or framework.

Every shared Button menu receives this behavior: screen and catalogue WorkMenu roots, nested watch/reading/game/music/list/personalisation actions, row-style menus, account/status menus, queue/friend actions and settings menus. A nested menu that is mounted inside an open parent also owns no glass action until that nested menu opens. Ordinary non-menu Button materials retain their existing binding and behavior. MediaCard, WorkMenu, their domain components and Shelf/source code are unchanged.

Closed popovers are `display:none` in [app.css](/Users/admin/Documents/ChatGPT/coast-new/src/app.css:313); there is no closing animation to preserve. Opening constructs the same glass variant synchronously during Svelte's action update, and the controller retains its existing post-tick placement/focus pass. Closing disconnects only material ownership. Pointer leave does not close/unmount a menu; keyboard, compact/touch nested navigation, selected drafts, commands, playback and anchored cards retain their existing code paths.

## Current source correction and resource boundary

The original UIS-04 report's menu-controller breakpoint-listener claim is historical. The current [controller](/Users/admin/Documents/ChatGPT/coast-new/src/lib/ui/controls/menu.svelte.ts:297) already adds its media-query listener, ResizeObserver, outside watcher and positioning listeners on open and removes them on close. Its closed `compact` getter reads current `query.matches`. That prior repair is protected by the existing menu-lifecycle test and must not be counted again here.

The separate remaining path was the always-mounted menu **material** action. [liquidGlass](/Users/admin/Documents/ChatGPT/coast-new/src/lib/ui/materials/glass.ts:330) creates one ResizeObserver and one settings-watcher membership per action even for a closed, zero-size menu. Settings watchers share a global MutationObserver and appearance media-query listener; there was not one such global listener per menu. The new binding removes the closed menu's material ResizeObserver and watcher membership. Other open/permanent glass surfaces can correctly keep the shared global observer/listener alive, so this is not a claim that application-wide listener count reaches zero.

Native SVG deletion follows the existing five-hundred-millisecond deferred cleanup; it is not changed to immediate deletion. A rapid reopen gets a newly owned filter, and old cleanup must remove only its captured old SVG. The action's cached displacement map is released with the closed action, so reopening recomputes its map/definition instead of retaining the warm action. That is an explicit tradeoff for removing closed ownership; no net CPU/GPU, heap, frame-time or latency improvement has been measured. This slice complements the prior `UIS-06` unchanged-definition reuse while open; it is not a second count of that reuse gain.

## Separate remaining UIS-03 / UIS-04 work

MediaCard still latches `active` after first hover/focus/action and retains WorkMenu. That cannot safely be reset on pointer leave: ScreenActions and CatalogueActions keep pending primary operations plus reading/request/progress/metadata/planning/sharing dialogs outside the menu children, and WorkMenu's exported busy state currently covers only the catalogue side. Closing a menu can intentionally hand off to one of those owners. A broader mount change must first represent all engagement lifetimes, or retain domain owners and gate only transient presentation through existing owners. It must prove pointer/focus/touch transitions, async primary actions, menu→dialog drafts, late replies, playback and permission withdrawal across all media. No such broader change is made here.

Shelf append/prepend still retains arrays and every keyed card. `createDetailSource` preserves `entryId` occurrence identity, loaded first-page state and bidirectional episode focus; `createShelfLayout` adjusts the retained first element when prepending. Cursor/grid, local data and variable journal cards have different navigation contracts. A generic truncate-to-page-size or card unmount on hover would change those behaviors. A real retained-page/window policy needs stable scroll spacers/anchors, backward reload cursors, focus/open-owner pinning, complete occurrence identity and Back/filter/revision semantics across adapters. Replacing grid pagination and explicitly sliced twenty-item rows are separate healthy paths.

The existing lazyContent/Shelf activation signal remains once-only; offscreen optional social/revision reads are not automatically suspended. A future visibility/dirty-refresh slice must retain immediate privacy withdrawal and owned active menus/playback, and change the canonical signal/contracts across adapters rather than a per-medium exception. Actual multi-page DOM/owner growth and unseen→visible→offscreen→revision→visible HTTP traces were not captured in this slice. No Shelf/card retention, offscreen request, transferred-byte or twenty-page resource saving is claimed.
