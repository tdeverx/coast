## Adopted portion: shared imported-listen persistence

[Original proposal and measurements](candidates/admin-listen-batches/RESULT.md), [final effect acceptance](candidates/admin-listen-batches/EFFECTS-RESULT.md), [frozen final patch](candidates/admin-listen-batches/final-candidate.patch) retain the archived methods and receipts.

The shared music persistence owner now inserts deterministic imported occurrences in batches of at most 100. Progress increments only for rows actually inserted. Returned rows are mapped by occurrence batch identity so native webhook preparation follows submitted occurrence order rather than relying on SQL RETURNING order. Every importer consumer continues through the existing shared importMusic/reconciliation path; single manual listens retain their existing owner and semantics. No parallel writer, scheduler, compatibility layer or new persistence model is introduced.

The original native import/reconciliation comparison covers controlled deltas 0/1/100/10,000 over the real admin, account and catalogue track, replay, decreasing counts that preserve history, generation fencing, lease mismatch and transaction rollback. Its 43 checks pass. The [exact final-source rerun](candidates/admin-listen-batches/FINAL-MEASUREMENT.md) passes the same 43 checks. At 10,000 controlled listens, statements fall 30,031→10,231, history INSERTs 10,000→100 and progress writes 10,001→101. Single-run elapsed is 28.58→19.10 seconds; global WAL samples are 13,531,128→11,839,728 bytes. Earlier receipts remain distinct and immutable. Single-run times and global WAL observations are finite local measurements; they are not production tails, contention, CPU or heap guarantees.

Final effect acceptance adds 30 checks with existing deterministic occurrence indices 0,98,99,100,101,199,200 and target 205. Both versions add exactly 198 missing listens. A temporary admin subscription prepares native webhook outbox rows without delivering them: complete payloads, occurrence association and submitted order match. All social projections and final progress match. Actual trigger inventory shows only content-revision triggers on music_progress; revisions coalesce to the same one tracking and one social increment per transaction. Failure at the 100th prepared webhook rolls back history, progress, social state, outbox and revisions exactly. The active-subscription correctness run has adverse single-run elapsed samples, 728→1,012 ms; it is retained and no universal speedup is claimed.

**Remaining PJ-08 contract:** batching statements does not bound the whole-track transaction. A 10,000-listen target still writes 10,000 history rows before the final shared reconciliation commit. Publishing the full remote count after only the first 100 would make the current baseline skip the remaining 9,900 on resume; inventing an intermediate remote count would alter provider evidence. Resumable partial history/progress, a fenced pending occurrence interval and concurrent-listening semantics require an explicit durable contract. That portion stays on the backlog; no alternative is investigated in this run.

## Rejected methods: retain defaults

[Notification execution](candidates/admin-notification-batch/outcome.md) uses four actual passive recipients and the admin initiator. Stable complete writer values and replayed source-key upsert identity match. A controlled preference change after the first write yields a silent second notice under DEFAULT but a normal notice in the batch candidate. A later CHECK failure leaves one earlier DEFAULT notice versus zero candidate notices. Savepoints emulate independent statement survival inside an outer rollback; no real notification delivery is performed. All original 518 notices and preferences/configuration are restored. The reduced query count does not justify silently changing those contracts. Preparation-read/lost-ack and 100-recipient tests stop after this required failure; no alternate method is tried.

[Party execution](candidates/admin-party-liveness/README.md) uses the actual admin as sole actor and an actual peer only as passive membership. Controlled deletion of their friendship happens only in a marker-owned copy. Unchanged admin-only result/state matches. After revocation, the candidate retains joined=true where the native path stores/returns false, despite unchanged heartbeat flags. Statement samples 10→8 and lower single local times are not accepted gains because authorization behavior differs. No playback, provider session, media reply or peer command is fabricated. The remaining broad contention/media acceptance is not run after this failure; default retained.

## Deferred gates, distinct from measured failures

Live keysets can admit newly eligible work or lose originally admitted work after generation changes. Lost acknowledgements also change replayed accounting. The prepared selection shape is intentionally not executable: durable admitted IDs, command identity, continuation and receipt ownership remain undefined. No actual-data performance run occurred, and the user-kept Tasks query/index pair stays unchanged.

[Projection preview candidate](candidates/admin-projection-preview/outcome.batch23.md): the private candidate narrows browser entries and builds a conflict-ID Set while leaving complete durable evidence and approval/execution owners unchanged. Native preview always verifies the real provider profile and reads current remote collection state; approval also rechecks it. This batch disables provider transport, so it cannot validate those branches with stored test rows alone. No fabricated adapter responses, normal writes or adoption are claimed. Genuine provider acceptance and browser transfer/panel/lifetime measurements remain deferred; this is not a measured optimization failure.
