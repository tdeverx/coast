# Admin taste score menu

The **Calculate taste score** action belongs to the media card’s Admin submenu. Rendering a card, opening its menu and hovering Admin must issue zero taste requests. The shared work menu checks the signed-in Coast admin role and Personalisation capability. The game, reading, music and screen menus pass their existing catalogue identity to the action. A verified collection uses its group identity. A provider item needs a resolved Coast identity before the action can run.

Selecting the action mounts the shared taste dialog for that item. The dialog owns the read and sends an abort signal when it closes or unmounts. The admin endpoint validates the work or group, checks the Coast admin role and scores only against the authenticated viewer’s private reference. A username in the URL cannot select a different owner. The diagnostic recomputes the fit from the saved medium reference and current local candidate metadata. It performs a read and leaves the published score in place. A collection or comic volume samples up to 24 distinct members under the viewer’s category permissions. The response uses `Cache-Control: private, no-store`.

## Local verification

The two PostgreSQL suites passed 15 tests with 119 assertions in disposable databases. A stale fixture held a published 7% match. The admin request recomputed the fit and the subsequent normal lookup still returned 7%. Other cases cover ordinary-user denial, the admin’s own result, unavailable results and private response headers. A direct anonymous API request returned 401, and the public-read-only route list excludes the endpoint. Dialog tests cover a single request after selection and cancellation on close. Chromium with synthetic accounts observed zero admin score requests through admin sign-in, item open, menu open and hover over Admin. Each selection sent exactly one request. The dialog displayed a 70% match for one item and an unavailable result for another. The signed-in member saw neither the Admin submenu nor the action, sent zero score requests through the same item menu and received 403 on a direct request.

The existing full-history worker and card-batch benchmarks measure a different operation. This review covers local menu demand and authorization. Production latency and physical-device rendering still require separate observations.

Closing the personal signal browser cancels its outstanding page request. Item tests and profile panels recheck the viewer and enabled medium when the session changes. If a friend withdraws access while their profile is open, an unavailable response for that same profile clears the prior comparison. The browser bundle contains the dialog and its API calls; the scorer and saved reference stay on the server.
