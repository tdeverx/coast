# Frontend performance audit

Scope: read-only inspection of `/Users/admin/Documents/ChatGPT/coast-new` at HEAD `4322f5c907401f21dafc379b4f87d5f5fcb7bf1c`. Uncommitted material changes were excluded; the material lifecycle was read with `git show HEAD:...` only. Trials and harnesses are under `/tmp/coast-performance-snapshot/scripts`. No live services, databases, providers, Git state, or production dependencies were changed.

The measurements below establish JavaScript work and request-count scaling. They do **not** establish the source of observed browser CPU/RAM spikes or container heap growth. Browser layout, painting, image/video decoding, real network latency, and native media buffers were not measured.

## Small changes supported by isolated measurements

1. **Journal visibility filtering repeatedly scans the entire date list.** [journal.svelte.ts:43](/Users/admin/Documents/ChatGPT/coast-new/src/lib/ui/shelves/journal.svelte.ts:43) creates unique days, then line 44 uses `days.indexOf(...)` for every event: O(events × distinct dates). It also does this when `maxDays=Infinity`, the grid-history/profile setting ([profile page:355](/Users/admin/Documents/ChatGPT/coast-new/src/routes/profile/[username]/+page.svelte:355)). Appending history retains the full list at lines 53–54, so the cost increases with browsing depth.

   Smallest fix: return `loadedItems` for unlimited days; otherwise make a Set of the allowed days and filter with `Set.has`. Keep event order, unknown-date handling, selected history entries, and grouping unchanged. The isolated trial preserves event IDs for negative, zero, one, fractional, twelve, NaN, and unlimited limits, including unknown dates. Finite seven-day filtering measured 13.568 ms → 0.380 ms for 6,000 synthetic events, and 335.682 ms → 1.728 ms for 30,000 events. Unlimited filtering measured 13.509 ms and 327.618 ms respectively → effectively zero for the bypass. These are stress sizes, not measured user data sizes. The test excludes `journalGroups` and DOM rendering.

   Files: [harness](/tmp/coast-performance-snapshot/scripts/journal-filter-benchmark.ts), [results](/tmp/coast-performance-snapshot/scripts/journal-filter-benchmark-results.json), [reviewable trial patch](/tmp/coast-performance-snapshot/scripts/journal-filter-trial.patch). The patch has not been applied to the main checkout.

2. **Every mounted card registers a capturing global scroll listener.** [MediaCard.svelte:161](/Users/admin/Documents/ChatGPT/coast-new/src/lib/ui/components/MediaCard.svelte:161) installs `contextGesture`; [context-gesture.ts:64](/Users/admin/Documents/ChatGPT/coast-new/src/lib/ui/context-gesture.ts:64) adds a window scroll listener per action. Every callback calls `clearTimeout` at line 9 even when no touch hold exists. A rail scroll is captured at window, so this work scales with all mounted cards, including cards outside the viewport.

   Smallest fix: register global scroll cancellation when a qualifying touch hold begins and remove it whenever that hold ends or is cancelled. The isolated patch changes three lines. For 600 cards × 2,000 fake scroll events, the baseline ran 1,200,000 callbacks/timer clears (7.120 ms median across five runs); the trial ran zero (0.069 ms dispatcher overhead). For 3,000 cards: 6,000,000 callbacks, 34.165 ms → zero callbacks, 0.070 ms. This is a synthetic fake EventTarget dispatch benchmark; it is **not** a browser frame-time claim, and the total baseline time is spread across 2,000 events.

   Both implementations passed eight modeled checks covering mouse hold, touch movement/scroll cancellation, stationary touch opening once, suppression of the post-hold click, keyboard context opening, and listener/timer cleanup on destroy. Browser acceptance should additionally exercise native context click, touch cancellation over nested scrolling rails, and keyboard focus/menu behavior.

   Files: [harness](/tmp/coast-performance-snapshot/scripts/client-lifecycle-benchmark.ts), [results](/tmp/coast-performance-snapshot/scripts/client-lifecycle-benchmark-results.json), [reviewable trial patch](/tmp/coast-performance-snapshot/scripts/context-gesture-trial.patch). The baseline imports the original snapshot action; the trial is separate.

3. **Appending cards re-requests social enrichment for the entire accumulated list.** [Shelf.svelte:98](/Users/admin/Documents/ChatGPT/coast-new/src/lib/ui/components/Shelf.svelte:98) derives all work IDs, clears `social`, splits the full list into batches of 60, and sends every batch concurrently at line 105 whenever `displayItems` changes. The actual extracted effect, executed with a fake API, made 55 requests covering 3,300 IDs for ten successive 60-item pages; twenty pages made 210 requests covering 12,600 IDs. Thus the work across n appended pages is triangular. A missing-ID-only trial count is ten requests/600 IDs or twenty requests/1,200 IDs respectively.

   Smallest candidate: keep per-shelf results while appending and fetch only IDs not already enriched; retain a record for queried empty results too. Clear/refetch on a relevant social revision, user/category change, or explicit refresh, so reactions/privacy/presence remain fresh. Do not introduce an indefinite global cache. If a large backlog can arrive at once, bound batch concurrency. Only the missing-ID request-count prototype was measured; a production cache invalidation policy was **not** implemented or tested. The shared harness/results above contain the request counts. Acceptance: append requests scale linearly, existing badges stay visible during requests, explicit social changes refresh old IDs, failed requests can retry, and aborted/outdated responses cannot overwrite the current selection.

## Confirmed refresh behavior requiring an isolated browser check

4. **Unrelated session refreshes trigger content refresh/reset effects.** The root [layout.svelte:70](/Users/admin/Documents/ChatGPT/coast-new/src/routes/+layout.svelte:70) invalidates `coast:session` every 60 seconds while the tab is visible; [layout.server.ts:7](/Users/admin/Documents/ChatGPT/coast-new/src/routes/+layout.server.ts:7) declares that dependency. [progress.svelte.ts:85](/Users/admin/Documents/ChatGPT/coast-new/src/lib/ui/shelves/progress.svelte.ts:85) tracks broad `route.data` and reloads activated shelves with no initial data. [experimental.svelte.ts:21](/Users/admin/Documents/ChatGPT/coast-new/src/lib/ui/shelves/experimental.svelte.ts:21) likewise reloads every activated experimental shelf on broad `page.data`. [DynamicFeed.svelte:19](/Users/admin/Documents/ChatGPT/coast-new/src/lib/experiments/DynamicFeed.svelte:19) clears all accumulated row definitions on the same broad dependency. For You has several such sources ([page:35](/Users/admin/Documents/ChatGPT/coast-new/src/routes/for-you/+page.svelte:35)). This supplies a plausible periodic burst and an experimental-feed reset; no browser trace was taken.

   Narrow content refresh to explicit relevant tracking/social revisions or refresh keys, while retaining initial-data replacement. A purely local mutation counter would miss server/provider-driven changes, so preserve an appropriate server change signal before replacing the broad subscription. Browser acceptance: advance a controlled clock through two session-only refreshes and verify no content requests/row resets; tracking/social revisions must still refresh affected content, preserve selected filters, and prevent stale responses from publishing. Do not remove the session refresh or blanket-disable invalidation to hide the burst.

## Browser RAM/CPU hypotheses, separate from container heap

5. **HLS.js playback has no application-defined historical buffer cap.** [PersistentPlayer.svelte:377](/Users/admin/Documents/ChatGPT/coast-new/src/lib/ui/components/PersistentPlayer.svelte:377) constructs `new Hls()` with no options. The local lock pins HLS.js 1.7.3 ([bun.lock:231](/Users/admin/Documents/ChatGPT/coast-new/bun.lock:231)); its primary implementation defaults `backBufferLength=Infinity`, forward buffer target 30 seconds / 60 MB, and maximum forward duration 600 seconds ([local config:455](/Users/admin/Documents/ChatGPT/coast-new/node_modules/hls.js/src/config.ts:455)). [buffer-controller.ts:1508](/Users/admin/Documents/ChatGPT/coast-new/node_modules/hls.js/src/controller/buffer-controller.ts:1508) enables duration-based historical flushing only for finite back-buffer length. This proves the configuration lacks an application cap; browser quota eviction may still limit retained buffers. It does **not** prove a leak, a browser memory slope, or container RAM consumption. It applies to the HLS.js branch, not native HLS.

   Smallest trial: a finite back-buffer duration, for example 60–90 seconds, without changing quality or the UI. Tradeoff: older seeks must re-fetch segments; the duration is not a universal byte cap because bitrates differ. Validate backward/forward seeking, resumable positions, track/edition switches, streaming errors, and synced playback. Measure a controlled 20–30 minute high-bitrate fixture in a disposable browser: `buffered.start/end`, browser process/GPU memory, quota/stall events, and release after closing. Compare a finite-duration trial before selecting the cap. Existing media teardown destroys HLS and removes/loads the source at [player:405](/Users/admin/Documents/ChatGPT/coast-new/src/lib/ui/components/PersistentPlayer.svelte:405).

6. **Growing mounted collections amplify listener, image, menu, and age-label work.** Journal/social append sources retain prior items, and [Shelf.svelte:170](/Users/admin/Documents/ChatGPT/coast-new/src/lib/ui/components/Shelf.svelte:170) mounts every entry. Lazy images defer requests but do not unmount cards. [MediaCard.svelte:162](/Users/admin/Documents/ChatGPT/coast-new/src/lib/ui/components/MediaCard.svelte:162) permanently sets `active=true` after hover/focus; it never resets, enabling the material at line 215 and retaining the action component at line 239. The shared [clock.svelte.ts:10](/Users/admin/Documents/ChatGPT/coast-new/src/lib/ui/clock.svelte.ts:10) ticks each second; dated activity labels read it at [card:168](/Users/admin/Documents/ChatGPT/coast-new/src/lib/ui/components/MediaCard.svelte:168), although their text changes only at minute/hour/day boundaries.

   Measure DOM/listener/heap counts after loading 1, 5, and 20 pages, then after route departure and GC. Profile scrolling and a pointer-free idle interval separately. Apply the small listener/filter/enrichment fixes first. Only introduce windowing if retained-DOM/layout costs remain material, because it adds focus and scroll-restoration complexity. A separate minute clock for relative age labels could preserve the one-second clock for countdowns. Any hover cleanup must keep open menus, touch actions, and keyboard focus alive; do not simply reset `active` on pointerleave.

7. **The last trailer source stays attached while its persistent root video is hidden.** [hero playback:24](/Users/admin/Documents/ChatGPT/coast-new/src/lib/ui/heroes/playback.svelte.ts:24) unloads only when URL/ID changes or the owner is destroyed; hidden/foreground effects at line 45 merely pause. Route hero cleanup changes `visible` at [presentation:160](/Users/admin/Documents/ChatGPT/coast-new/src/lib/ui/heroes/presentation.svelte.ts:160). This retains at most the current trailer source, not an unbounded sequence. A paused native video can retain native media buffers, but this was not measured. Compare browser memory before trailer playback, after navigating to a route without a hero, and after explicit source release. Only add an idle release if meaningful; preserve trailer pause/resume and route-transition behavior.

## Existing lifecycle safeguards worth preserving

`createResource` aborts prior requests and prevents stale publication ([resource:29](/Users/admin/Documents/ChatGPT/coast-new/src/lib/ui/resource.svelte.ts:29)); shelf owners cancel on destroy. `lazyImage` shares one observer and removes callbacks/disconnects on the last detached image ([lazy-image:4](/Users/admin/Documents/ChatGPT/coast-new/src/lib/ui/lazy-image.ts:4)). Credits cache has an eight-entry cap ([credits:68](/Users/admin/Documents/ChatGPT/coast-new/src/lib/ui/shelves/credits.svelte.ts:68)); discovery caches only the finite set of surfaces. Menu geometry observers exist only while menus are open and clean up. Crop sampling uses 320×180 frames, checks hidden/paused state, and cancels during source teardown; its recurring work is a profiling candidate, not an established spike. No evidence here supports replacing these with new dependencies or redesigning the approved UI.
