# Details fallback and diagnostics

Base application commit `8a19062`.

A read-only count on live Coast found 19 identical feedback entries in nine seconds. The optional Screen Details refresh treated a saved-data fallback like a failed user action. The page and overlay keep their saved projection on enrichment failure. They emit no toast or inbox entry for that fallback. Server diagnostics record the metadata refresh stage, provider HTTP status or recognized database code when available. Initial load and user action failures still use their original feedback paths.

The diagnostic pass labels playback, subtitle and other API operations without copying dynamic paths. It preserves slow streaming requests at Info and moves fast stream successes and cancellation to Debug. Provider events record queue wait, browser events identify the error source, and job failures include the task kind and retry state. Jellyfin reconciliation distinguishes provider reads and writes from local reconciliation. IGDB enrichment distinguishes provider lookups from metadata import. The secure store, rate and rotation limits, and redacted export remain authoritative. These changes add no queries or provider calls.

The follow-up review covers the HTTP, provider, browser, player, reader, backup, queue and runtime boundaries. The server generates a separate ID for each HTTP call and captures it before streamed body work can outlive request context. Routine traffic leaves capacity for warnings and errors within the existing 128-record queue. The same bounded error-code classifier covers database wrappers and common storage failures. Reader archive failures after headers, browser transport and malformed responses, and scheduler or cleanup failures produce safe events at their owners. No query, provider request, periodic timer or external collector is added.

Validation covers severity admission under load, ID isolation across overlapping requests, classified outcomes and redaction, optional enrichment across navigation lifetimes, and saved content without feedback in the controlled browser fixture. The built app and a disposable PostgreSQL database verified live level changes, authenticated diagnostic download, request ID scope and redaction. Targeted integration suites cover playback and reading shares, platform logging, public API, runtime SQL, Jellyfin reconciliation, Steam and backup restore. The live inbox count establishes the incident size. Verification of the changed behavior used local fixtures.
