# Admin Taste breakdown

The existing admin recalculation reads the same saved viewer reference and local title metadata as the score. It records the weighted fit before evidence shrinkage, its adjustment toward neutral, the applied ratings adjustment and the final score. The diagnostic shows each matched category's share of the effective weight after the context cap, along with the strongest inputs and their supporting title counts. It shows the strongest rating-model inputs before rounding and the cap. When the scorer withholds a match, the diagnostic explains the evidence gate and shows any context that matched.

A collection inspection reads the same sample of at most 24 titles. Its diagnostic lists the scored and unscored titles, the average of the scored titles and the viewing bonus for screen collections. It calculates member scores without building a separate per-feature trace for each member. The diagnostic payload is private and returned through the existing admin permission check. Ordinary title reads, published scores and background jobs skip trace construction. The trace uses the published scoring formula and revision.

Tests compare inspected scores with ordinary recalculation and cached results, check the score arithmetic and rating terms, and exercise scored and withheld collections. The local popup fixture renders the application components with representative title and collection data. Database fixtures exercise the authenticated service boundary and metadata path separately.

A paired CPU-only check used a prepared reference from 300 synthetic rated works and 72 in-memory catalogue titles. Across 32 alternating samples after ten warm-ups, ordinary scoring took 1.21 ms median and 2.07 ms p95 for the 72-title batch. Scoring with traces took 2.90 ms median and 3.63 ms p95. Scores, evidence and ordinary explanations matched for all 72 titles. The largest single trace in this run encoded to 9,933 bytes of uncompressed JSON. The popup collects a full trace for an individual title. Collection members use ordinary score summaries. These timings exclude metadata reads, network, rendering and live application load.
