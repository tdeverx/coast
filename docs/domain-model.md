# Canonical data and tracking

The [build brief](brief.md) is authoritative. The PostgreSQL schema is defined in `src/lib/server/db/schema.ts`; its generated initial migration is in `drizzle/`. Bun's SQL client and Drizzle are created lazily, so compiling the app does not open a database connection.

Every movie, show, season, episode and collection has a Coast UUID. Concrete subtype tables describe the television hierarchy. Alternate episode orders reference stable episode UUIDs. Provider mappings, snapshots, administrator metadata, field locks, and personal presentation preferences are separate records. A provider refresh cannot erase an override.

The JSONB column codec follows Bun SQL's native parameter contract: native objects are serialized once, and scalar values retain their JSON types. Tests verify PostgreSQL's stored `jsonb_typeof` and JSON operators, because an ORM-only round trip can conceal an incorrectly stored JSON string.

Tracking services serialize each user's changes with a PostgreSQL transaction advisory lock. Accepted events and their projections commit together. The source-event identity is unique per user and source; concurrent import retries therefore append once and count one play. Unwatching changes current state but retains historical play count and events. Imported contradictions are recorded as unapplied events with a review reason. Manual destructive or out-of-order changes require acknowledgement.

Single-item, bulk and rating services expose transaction-aware entry points for atomic outbound actions. Bulk results identify only the newly accepted canonical child events; a no-op returns no exportable event. Resolved imported reviews retain the original payload and review decision, and retrying that source event cannot reopen a resolved review.

The ordinary saved movie watchlist lasts until completion. A completed regular episode removes its show from the unstarted watchlist presentation while preserving saved intent. Dropped state survives no-op writes. Season/show completion excludes specials by default; explicit special episode tracking remains available. Bulk collection tracking resolves its movies and episodes once, so nested or repeated membership cannot duplicate plays.

Manual shows can gain a season and a desired number of episodes from 1 to 100. This only fills missing canonical identities; lowering the requested count never removes episodes. Season zero creates specials. Provider-backed shows use provider refresh instead. Adding regular episodes recalculates current completion without erasing previous viewing history.

Ordered list edits lock the owner’s list row. A full reorder requires an exact permutation of its current items, so stale clients cannot silently remove or introduce entries. The page's earlier/later controls swap adjacent items in the server's current order, including across page boundaries, without sending the entire list to the browser. Half-star ratings are enforced both at the service boundary and by a database constraint.

Metadata editing checks the current persisted user role. Administrator changes can lock individual fields, suppressing personal presentation preferences. Null clears an override; omitted fields preserve it. The editor returns field provenance and source update times without returning raw provider payloads. Metadata source policy remains administrator-controlled.

Application read models batch metadata and per-user state for the selected media hierarchy. Shows inherit permitted episode availability; collections traverse their canonical relationships without duplicate progress. Home returns a playable regular next episode for show heroes and local same-genre suggestions based on Coast history. The queries enforce both availability ownership and connection ownership, and disconnected or disabled providers do not make a title playable.

Detail episode membership and the explicit full-list API resolve IDs in batches of up to 500; this batch size does not truncate membership. Library filtering and counts run in PostgreSQL before 60-title pagination, including permitted episode availability for shows. Source and tracking filters therefore cannot hide older matching titles behind newer catalogue rows. The actual search service uses the same original, administrator and user-title matching as the read model, ranks permitted availability before limiting results, and returns a truncation flag when more than 100 local matches exist. Home shelves and remote discovery/search remain bounded active result sets.

Lists loads names/counts for the sidebar and at most 60 media views for the selected built-in or custom list. Watchlist, favourites and collected filters select the user's state before pagination, rather than filtering an arbitrary recent-catalogue batch. List selection, watchlist filter and page live in the URL, so reload and browser Back restore them. The add-to-list picker uses `GET /api/v1/lists/summaries` and does not hydrate list contents. Requests similarly resolves at most 60 rows and their titles; scheduling its background Seerr refresh no longer reads the entire request history a second time. Library, Lists and Requests share the same pagination component.

Availability filtering expands the current user's permitted sources into title, show and season identities once per query. It does not repeatedly scan the episode library for every candidate title. Library requests still resolve only the selected 60 titles. Shared read models aggregate availability sources in PostgreSQL instead of loading every child episode for ordinary show/season cards; collection progress still resolves its complete descendant set. This applies to Library, Search, For You, Discover, lists and details. A fresh detail snapshot reuses its first read instead of loading the entire detail hierarchy twice.

Shared media cards, episode thumbnails, request posters and search-preview artwork defer their URLs until within 300 pixels of the viewport and decode asynchronously. Hidden mobile search artwork is not requested. The active hero remains eager. Route data preloads only on an intentional tap/click, so moving across cards does not fetch full details or refresh provider metadata.

Run `bun test tests/domain.test.ts` for pure rules. Set `TEST_DATABASE_URL` to an isolated PostgreSQL database for `tests/domain-db.test.ts`; it migrates the database and inserts/cleans only uniquely named fixtures. The transaction tests cover concurrent imports, rollback, contradictory events, bulk completion, list ownership, metadata permissions, and stable manual episode identities.

The related `domain-application-db.test.ts` suite verifies scoped availability, home and detail actions, recommendation isolation, complete 501-item details/lists, bounded selected-list/request pages, cross-page moves, saved titles beyond 500 unrelated entries, and partial-show/collection filtering. `domain-jsonb-db.test.ts` verifies database-level JSON types rather than relying only on ORM return values. These tests exercise local PostgreSQL services; they do not prove real-provider interoperability or production-scale query performance.
