# Behaviour contracts

## Tracking

Completion is canonical; editions may retain their own seek positions. Each accepted change appends an event and updates the per-user projection in one transaction. Duplicate external events do not increase play count. An explicit rewatch may add a play. A no-op cannot undrop an item; genuinely changed progress or a manual state change can. Movie completion or one completed regular episode establishes meaningful progress and removes the ordinary unstarted watchlist presentation. Saved intent remains available for To Watch, In Progress, Complete and Dropped filters.

A partial rewatch retains canonical watched status and its existing play count while exposing the new position through Resume and Continue Watching. A completed position starts a fresh playback at the beginning; another play is counted only when that playback reaches completion.

Show and season completion use regular episodes by default, excluding specials. Explicit episode identity is independent of display order. Bulk watch/unwatch records individual canonical changes. Destructive or contradictory sequences require acknowledgement, and imported contradictions are retained for review instead of silently overwriting Coast history. Ratings are 0.5–5 in half-star steps; null removes a rating.

## Metadata

Resolution is user preference → administrator override → current primary provider snapshot → fallback provider data. An administrator lock suppresses the user preference for that field. Provider snapshots are never mutated by overrides. Local media-server metadata is preferred by default; the administrator may enforce TMDB-only metadata. English and the user's selected region are defaults, original titles remain searchable, and artwork choices are presentation preferences. Each snapshot retains source and update time. Partial search/discovery snapshots preserve richer detail fields; an explicit complete refresh may clear obsolete fields. Detail pages refresh missing or seven-day-old regional TMDB details. Collection members are loaded on a relevant collection details page and ordered by release date.

## Provider capability contracts

Adapters implement only supported capabilities: authentication, catalogue, metadata, availability, playback, scrobbling, tracking/list exchange and requests. Coast application services own canonical mapping and permission checks. Native fetch, boundary validation, deadlines and constrained responses are shared infrastructure; provider-specific behaviour stays in each explicit adapter.

Jellyfin scans checkpoint pages, publish per-user availability and reconcile disappearance only after a complete successful scan. An interrupted scan never removes the rest of a library. Trakt is explicit import/export after optional account linking; Coast remains authoritative. Imports keep source identities, survive disconnects and are idempotent. Seerr is linked to its destination media-server instance and enforces its own request permissions as well as Coast policy.

## Playback

Two application-level video elements survive route navigation: a dedicated hero trailer player and a title player behind the content. They have independent sources, positions, crop detection and play/pause state. Pausing the title reveals Coast and allows the visible hero trailer to play; resuming the title hides page content and pauses the hero. There is no separate UI mode switch. Navigation pauses a playing title before revealing the destination. Art remains until hero video/crop readiness; trailer pause/end returns to art. The same trailer is not restarted by a hero/details handoff. Trailer audio starts muted; explicitly unmuting either player mutes the other.

Full playback uses a Coast-owned session, obtains Jellyfin PlaybackInfo, evaluates every source and applies administrator bitrate/delivery policy. Starting a different title closes the previous session; resuming the same title reuses its video and session. Native-compatible direct streams are preferred when allowed; Jellyfin supplies transcoding and HLS, with hls.js only where native HLS is unavailable. Tokens remain server-side behind authorised relays. Edition and source/quality are distinct selectors.

During playing title playback, five seconds without pointer, touch or keyboard activity fades both playback controls and the header/navigation. Activity reveals them again. Paused playback, post-play, errors, active menus/dialogs and keyboard-focused controls keep the chrome visible. There is no Hide controls button. The persistent playback bar remains available while browsing; resuming returns to the title at its current position. Its compact glass layout shows artwork and title above a thin progress line. Hovering the centre or focusing its range control replaces the metadata with elapsed/remaining time and expands the scrubber. Touch devices expose the scrubber directly. A drag previews the position and commits one seek on release; keyboard adjustments seek immediately. Scrubbing keeps the controls visible. Source, subtitle, edition and crop actions live in Playback options, with a separate volume menu and Close at the far right of the main bar.

The shared page shell keeps an opaque black canvas outside the animated route content. It covers the full page on Library, Search and other screens without a hero; hero pages expose only the hero area, using the same responsive height token as the hero itself. Content gutters, shelf gaps and short pages remain black during navigation.

Playback sessions begin prepared. Accepting subtitles allows the source to load; the video’s actual playing event starts tracking and external reporting. Cancelling before that point stops the prepared session without viewing history or scrobbles. The client sends playback reports in order, and each session transition, canonical progress update and configured outbound intent commits in one transaction. Provider delivery remains asynchronous. Playback failure creates an administrator diagnostic and a concise user message. No FFmpeg runs in Coast. Subtitle defaults, preferred languages, the optional pre-play prompt, manual selection, provider labels, seek, crop and post-play use the persistent control layer. Crop detection requires agreeing bright frames with symmetric dark edge bars; dark scenes retain the full frame. The full-player crop toggle combines any established encoded crop with viewport fill.

Full playback starts with Crop enabled, matching the reference prototype; Fit preserves the entire encoded frame. Crop placement can extend beyond the viewport without a CSS maximum-width clamp. Dark or uncropped intros do not permanently end detection: sampling continues at reduced frequency until reliable bars are established, and pauses while the video is paused, hidden or in full-player Fit mode.

## Outbox and notifications

Actions have no default expiry. A worker claims work using PostgreSQL locks, preserving order per user/connection. New pending edits can replace obsolete edits with the same compaction key. Retry uses bounded exponential backoff, not dropped state. Permanent failures notify the initiating user; successful recovery resolves transient failure notices. Users can inspect/cancel pending work. No Redis or browser-offline queue is needed.

Notifications are persistent per-user inbox records with silent, normal or persistent presentation. Administrative unsilenceable notices override user silencing. Polling refreshes inbox, jobs and requests; WebSockets are unnecessary.

## Requests

Available media has Play/Resume as primary action. Unavailable requestable media has Request; partial shows have Request More. Each destination appears once with an optional 4K variant. Season scope prevents duplicates, and only authorised owners/moderators cancel requests. The request dialog has a checked-by-default watchlist checkbox. Requests always remain visible on the dedicated Requests page.

### Your profile

The account menu opens a private `/profile` page. Edit profile saves a display name, optional bio and avatar; avatar uploads are resized to 256 × 256 in the browser and accept bounded PNG, JPEG or WebP data. Each title’s context menu offers **Set as profile background**. The larger artwork header anchors identity near its lower edge and resolves that title’s existing backdrop, falling back to its poster; Clear background restores the neutral header. Appearance preference changes and resets preserve the profile.

All-time totals distinguish unique watched movie/episode titles from recorded watches, favourites and ratings. The journal groups individual applied watch events by UTC date and consecutive episodes from the same show into expandable groups. Entries show recorded UTC times and labels rewatches and imported sources, and retains history after an unwatch. Repeated no-op watch observations from sync do not inflate totals. Episode cards include the series, season/episode numbers and episode title. The overview resolves twenty favourites and defers activity until its rows approach the viewport. The overview shows only Today when it has activity, otherwise the most recent active day; View all retains the full journal. Each UTC day is a horizontal activity row with shared lazy artwork. Activity loads in batches of 60 events, merges episode groups across batch boundaries and deduplicates event IDs; reaching the loader fetches the next batch, with a manual Load more/Retry fallback. The full activity view uses the same rows and starts with one server-rendered batch. Other full views use 60-entry pagination.

Favourites appear before the journal and charts. Arrange mode reveals pin and earlier/later controls; normal browsing hides them. Favourites can be filtered to movies or shows (including seasons and episodes), pinned to the front, and reordered with earlier/later controls within the visible filtered group. Up to 50 favourites can be pinned; custom ordering supports 2,000 favourites. Changes affect only the current user.

The statistics Month / Year / All time picker scopes totals, recap, activity charts, genres and ratings without changing the journal or other rows; Month and Year mean the last 30 and 365 UTC days. Favourites remain independent. Ratings use their latest update date. Activity streams separately and reads local records only. Daily or calendar-month buckets cover Month and Year; All time uses months, switching to years for histories longer than two years. Selecting a bar opens that exact UTC period’s journal. Pending conflicts and show/season aggregate watch events are excluded. Genre counts use unique watched titles (episodes inherit show genres), and rating distribution follows the selected period. The donut includes the top six genres plus Other, with counts in the legend; hover/focus updates its centre and selecting a slice or legend link opens matching history. Titles can contribute to multiple genres; Other sums remaining genre memberships, so its filtered journal can contain fewer distinct titles. Charts retain their panels for sparse or empty periods and show their existing empty states. Recorded history is not an estimate of actual viewing time. No profile is publicly exposed and loading it does not trigger provider syncs.


Profile refinements include a vertical background-position preview with explicit Save/Cancel, a featured favourite with an optional note, and remembered period and favourite-type filters. Arrange mode exposes the feature control. The full activity view supports title/series search, movie/episode filtering and rewatches, preserving selected dates. Rating bars open the matching rated titles; the genre donut shows each slice's share of genre memberships. A compact recap counts recorded movie/episode watches and currently completed regular seasons with known completion dates. Month/Year comparisons use the preceding equally long period and appear only when both periods have at least three watches. These figures do not estimate hours spent.

### Future tracking foundations

`src/lib/media/model.ts` defines work, edition and activity-session contracts, category-specific wording, lifecycle states and validated progress units (seconds, pages, chapters, issues, episodes, percentage and minutes played). Card progress and primary actions use the shared helpers; ownership is not treated as proof that Coast can open a title. Provider read/write capabilities are explicit and the current adapters remain Film & TV only.

Books and comics are not enabled catalog types or working trackers yet. Games have an initial authenticated backend for IGDB search/import, local metadata, provider identities, private playthroughs and dated play sessions; see [Games backend](games.md). IGDB settings and game tracking reuse the existing integration dialog, library cards, detail panels, menus and progress/session dialogs. Their first implementation must add persistent progress/session storage, category-specific metadata and provider identities, and an actual tracking flow. The shared contracts are preparation, not a generic plugin framework. Category-specific units and genre taxonomies must remain separate in cross-media statistics; current profile queries cover Film & TV.

New tracking events distinguish the time an import was recorded from whether its completion date is known. Undated imported completions appear under Date unknown in all-time activity, without an invented timestamp, and do not enter dated charts or recent-period filters. Existing stored dates are preserved by the additive migration. An undated completion is not exported as dated Trakt history; the export reports the missing date instead of assigning today. Known completion dates continue to sync normally.


The profile reuses the shared shelf as Progress with Watching, Next, Finished and Dropped. Watchlist and Favourites have separate rows with media-type pickers. It fetches only when near the viewport; tab/filter changes preserve controls and the prior cards. Finished requires canonical movie completion or all regular show episodes watched; Dropped takes precedence. Profile Progress supports media-type filtering before 60-item pagination and always includes all items; it has no availability toggle. The title opens the same /progress grid, including the profile username.


Profile pickers own their loading/error state: favourites fetches only its list; the statistics period fetches only its totals and charts; Progress fetches only its status row. They do not navigate or invalidate the whole page, and saved preferences are patched independently. Activity on the main profile always shows the latest active day across all time. Stale picker responses are ignored. The Progress shelf reserves its populated height while loading or empty. Show status is verified from regular episode tracking (specials excluded): at least one watched or partially played episode is required to be started; all known regular episodes must be watched to be finished. Parent flags/counters cannot make an unstarted show qualify. Cards display completed episode counts, partial starts and an aggregate progress bar. Library status filters use the same rules.


Profile statistics form one horizontal, scrollable row of equal-height panels: summary and recap, watching activity, movie/episode mix, genres and ratings. The shared period picker sits above this row and still updates only statistics. Panels use the existing surface, border and radius; horizontal arrows, touch scrolling and scroll snapping keep the full set accessible on narrow screens.


### Shared rows and headers

`ContentRow` owns horizontal layout, card/panel widths, edge gutters, hover/focus clearance, scroll snapping and scroll controls. Controls disable at the ends and respect reduced-motion preferences. `RowHeader` aligns the title and optional filters together, with actions and navigation on the trailing side; it wraps on narrow screens. Rows with a destination use a linked title and trailing chevron instead of a separate View all link. Title size/weight use app tokens and fixed row labels use sentence case. Segmented pickers scroll when needed by default.

`Shelf` composes media cards into ContentRow and retains development-only artwork previews. Cast, episode, activity-day and profile-statistics rows share the same row layout. Search, Lists and relevant settings headings use RowHeader. Filtered shelves reserve their height during empty/loading states; ResizeObserver updates bounds as content/viewport sizes change. Rows own presentation; queries, lazy loading and independent picker state remain with their feature components. Episode season selection still replaces the title. No provider writes or navigation are introduced by the shared components.


The home Continue row has Watching / Next tabs and one menu for All / Available and media type. Finished and Dropped are exclusive to profile Progress. Watching contains partial movies/episodes (including rewatches) and the next episode within a started season. Up next contains only the next untouched season per show, the next ordered title in a started collection or playlist, and explicitly queued titles. Context menus add/remove explicit queue entries independently of saved lists. Accepted viewing progress or completion consumes a queued title and queued season/show/collection parents. Availability is permission-aware and filtering precedes pagination.

Continue titles open /progress with the active tab and filters. The row and wrapping grid share ProgressShelf, retain the previous cards while fetching, keep controls mounted, and remember filters per tab while mounted. The grid uses bounded 60-item pages and a collection hero; row previews show 20 items. Tab/filter changes fetch only the selected content. Queue membership is local to Coast, separate from provider-synced watchlist/favourites.

The profile Activity picker requests only the selected type, showing Today or the latest matching active day; Shows means episode activity and retains episode grouping. Its title link carries the selected type into full history.

Profile title destinations share the row presentation in wrapping-grid mode: Favourites reuses its picker and arrangement controls, Activity retains its media-type picker and dated journal cards, and Progress reuses its status picker and episode progress captions. Continue has a shared expanded view with bounded 60-item pages; selecting a status or activity type updates only that content and the expanded view URL. Loading text placeholders are omitted; reserved row space, aria-busy, actionable errors and genuine empty states remain.

Shelf retains its last completed items while busy by default. Shared row controls remain mounted; arrow boundary measurements wait until replacement content is ready, and empty selections retain the row height. Progress follows the same replacement behaviour as Favourites and surfaces fetch failures alongside the controls without discarding its current cards.

Expanded profile collections use the existing MediaHero, randomly chosen from unique items in the current filtered results (preferring backdrop artwork). Selection stays stable while more results load, changes with completed filter results, and is omitted for empty results. Hero selection requires no additional metadata fetch and does not block grid loading.

Lists opens as built-in Watchlist and Favourites shelves followed by custom lists. Each shelf fetches a bounded page near the viewport, filters independently, and links its selected type/status to a shared wrapping-grid view with a collection hero. Custom-list Arrange controls retain ordering and removal; list creation and deletion remain available. Type filtering is applied before pagination and ownership is enforced for every list content request.

For You has separate Continue, Watchlist and Favourites rows. The saved rows each have an independent media-type picker and lazy-load near the viewport. Continue uses thumbnail artwork. Hero primary actions always link to Learn More outside detail context; item-page heroes retain playback/request actions.

Row style overrides are owned by ContentRow, not individual shelves or development-only previews. Right-click a row header to select Shape, Artwork and Overlay, with a top-level Use default reset and independent defaults within each submenu. Shelf and WatchJournal render the resolved style; episode season-picker headers also expose the menu. Cast supports shape overrides only, and chart panels retain their panel layout. Defaults remain supplied by each row; overrides are local to the mounted row and do not modify account preferences.

Media row style menus include Artwork priority with all six Show/Season/Episode orders and a per-setting Use default. Priority applies to artwork and overlays without changing the card's media identity or playback target. Source artwork is kept separate per level until display time; absent levels are skipped. Continue defaults to Season → Show → Episode, while ordinary episode rows retain their existing episode-first defaults. The top-level Use default clears priority together with shape, artwork and overlay overrides.

Artwork selection exhausts the requested image type across the selected Show/Season/Episode priority before trying other image types. A season poster cannot hide a real show thumbnail. Parent posters/backdrops are not labelled as thumbnails in per-level source data; episode Primary artwork remains a valid episode still. If no requested type exists, fallback images follow the same level priority.

Artwork audit: default episode thumbnails, explicit row priorities, and TMDB fallback all check real images of the requested type before substituting parent backdrops/posters. Cached TMDB artwork maps are included in the batched presentation read model (subject to the configured source policy and TMDB cache setting). Overlay failures advance through same-type candidates rather than disappearing after the first failure. Playback artwork uses the shared permission-aware presentation read model; profile backgrounds try their poster after a backdrop failure. Hero backdrop-to-poster and title-logo-to-text fallbacks remain unchanged.

Continue’s Watching tab sorts by the latest known accepted viewing activity; next-episode cards inherit the show’s activity. Favourites use that same viewing recency first, then the date favourited, with a stable ID tie-break. Metadata refreshes and unrelated tracking-state changes do not affect these orders. Partial rewatches remain in Watching.

Profiles use existing unique, case-insensitive login usernames at /profile/<username>; /profile redirects to the signed-in account. Signed-in users may read other enabled profiles, their activity, favourites, charts and Continue tabs. Every filter, chart drill-down and expanded grid retains the selected username. Owner-only editing, arrangement and media actions are omitted on visitor profiles; profile writes always target the authenticated account. Media availability and provider artwork are resolved with the visitor's permissions while displayed tracking state belongs to the profile owner. Missing or disabled profiles return 404; unauthenticated visitors must sign in.

Dropped includes explicitly dropped movies, shows, seasons, episodes and collections; the Shows filter includes seasons and episodes. Episode and season cards retain show context. Tracking menus name each drop/restore target explicitly and expose parent season/show targets where applicable. Dropping or restoring a parent changes that parent's state without rewriting independently dropped children.

Movies, shows and collections support a per-user rewatch start timestamp through Rewatch. Episode and season menus resolve to their whole show. Start now or choose a past date; Remove from Continue ends the run and preserves its history. Lifetime watched projections, ratings, history and play counts are not reset. Displayed completion and resume positions use dated activity since the boundary; undated/older events do not count. Show rewatches begin with the first regular episode in Watching, then follow the existing season hand-off to Next. Collection rewatches suggest the first remaining ordered movie or episode in Next. Their boundary only affects collection progress and playback; member titles retain their normal watched state elsewhere. A newly accepted manual completion counts one rewatch play; repeating the same completion is a no-op. Rewatch boundaries are local to Coast for now and do not export unwatched changes to providers.


Collections and playlists share an ordered playback sequence. Explicit collection positions and playlist entry positions take precedence; shows and seasons expand into regular episodes in place. Explicitly included specials remain in the sequence. Cycles terminate safely. Next selects the first unfinished, non-dropped entry; availability never silently advances the sequence. An unavailable next item offers an explicit Skip this item action for that playback traversal. Skipping does not create watched history.

Create a custom list as a Playlist to enable ordered playback. Each playlist entry has its own identity, including repeated titles, so moving or removing one occurrence leaves the others intact. Playback sessions and tracking events retain the sequence context; playlist progress and completion belong to the individual entry and survive reordering. Play playlist starts or resumes the current run; Start again begins a new dated run without deleting history. Playlist cards start at their selected entry and then continue in order. Playlists remain local to Coast, rather than flattening repeated entries into provider lists.

Library contains accessible server content. Personal Collection includes meaningful saved relationships and retained activity, even when items are unavailable. Add to Collection sets direct Collected status; Remove from Collection removes only that status and preserves other relationships and history. Named screen collections/franchises remain separate metadata groups. [Collection and Library](collection.md) defines membership, availability, missing demand and Trakt projection; [Music](music.md) defines listening and audio queue behaviour.


### Media action menus

Cards, heroes and selected seasons share nested glass menus, with no title/status header. Playback is unchanged. Mark watched offers Right now, release/air date when known, and Choose date. These actions affect the opened item, with confirmation for a whole season/show/collection; air-date batches use each leaf's own date and skip undated or future releases. Normal tracking/export pipelines remain in use.

Watchlist and Favourites are root toggles. Add to Continue queues the whole work in Next, restoring it if dropped. Episode and season Continue/rewatch actions resolve to their show; movie and collection actions retain their own scope. Remove from Continue drops the whole work and ends its active rewatch in one transaction, preserving watched events and playback history. Undo restores the prior drop status, rewatch boundaries and removed queue entries, and rejects stale undo after newer tracking or rewatch changes. Collection removal does not drop its member titles.

Lists shows owned lists directly with membership checkmarks; playlists use repeatable Add to actions. The list section scrolls independently, followed by contextual entry management. Lists is disabled when the user has no lists; creation belongs on the Lists page. Rewatch and History appear directly at the root. Rewatch starts the whole work from now or a chosen date. Play / Resume contains Reset playback position after a separator, disabled when no saved positions exist. Reset only clears saved positions, with confirmation; it preserves watched status and history. There is no manual position editor, Stop rewatching action, or separate Drop scope menu. Rewatching a whole show supersedes earlier season/episode boundaries and restores it from dropped status.

The root groups playback/request, watched/Rewatch/History/inline rating, Continue/Watchlist/Favourites/Lists, navigation/personalisation, and admin tools with separators between groups. Continue uses consistent Add to Continue / Remove from Continue labels for every item type. Jump to appears lower in the root menu and names the current episode, season and show destinations explicitly, omitting the page already open. Edition details remain available. Personalise contains Set as profile background and private overrides; Admin contains shared maintenance and only appears for administrators. Requests retain their own branch and permitted cancellation actions.

Desktop submenus use flyouts; narrow/touch screens use Back navigation. Destructive resets/removals remain red; reversible Continue removal uses normal styling. Success feedback appears only in toasts, never inline in menus. Action errors remain inline. Saved-list membership and supported list changes retain Undo; playlist removal requires confirmation because occurrence history cannot be recreated. History uses a dedicated lazy activity page with dates, grouped episodes, progress/unwatched events and pending-review records. All menu queries read local records without provider syncs.

Playback, Request/Request more, and Reset playback position retain stable menu slots when unavailable. Disabled actions expose a reason on hover and to assistive technology during keyboard focus. Request state uses local configuration and known movie availability/request status; show request options are validated by Seerr when opening the request dialog, since partial show availability does not establish completeness. Existing request management stays accessible.

Request menus use Request, Request more, Requested, or Manage request according to local availability, existing requests and cached account permissions. Management actions are scoped to a request; multiple requests are named by season/version, adding destination names only to disambiguate. Status appears beside View request rather than as a provider heading. Cancellation and decline are separated and red; approval appears only for managers. Additional season/standard/4K options are fetched only when opening the request submenu and shown only when requestable. The dialog reuses those options and preselects 4K for the 4K action; submission still revalidates permissions through the provider pipeline. Existing request editing is not exposed because the adapter does not support it. Cancelled/declined records do not keep the root in a management state.

### Shared menu conventions

Media cards (including episodes), heroes, quick previews, and selected-season/collection controls use MediaActions. Account, player, row style, and row filters use the same ContextMenu/MenuAction building blocks. Submenus use shared label/chevron layout, long names wrap within the viewport, and tall menus scroll. Single-choice settings keep checkmarks; toggles with explicit action labels do not need a second state marker. Related groups use separators instead of decorative headings. No success feedback is rendered inside menus. Disabled actions with explanations remain keyboard-accessible and tapping them shows the reason in a toast. Rewatch date dialogs name the entire show/collection and preserve history. View request links filter the Requests page to the selected owned request, with an All requests link to return; invalid identifiers are rejected and other users’ requests remain inaccessible.
