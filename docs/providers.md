# Provider boundaries and verification

Coast services own identity, permissions, local state and durable work. Adapters accept a server-only transport, validate response shapes with Valibot and return typed capability data. No provider credential is part of a browser DTO. Concrete adapters live in `src/lib/providers/{tmdb,jellyfin,trakt,seerr}`.

TMDB discovery retains relevant snapshots and canonical identities. Detail ingestion loads show seasons and episodes, original titles, regional certificates and collection membership. Snapshot updates never modify administrator overrides. A shared external identity is locked during concurrent ingestion; contradictory identity mappings fail for review. Search includes local titles, original titles and stored provider titles, with per-user availability first. Seerr discovery is a fallback for a linked user when TMDB is not configured. Local search remains usable during provider outages.

Jellyfin connections bind a Coast user to a verified server identity and encrypted account token. A scan checkpoints each successfully applied page; only a complete full scan invalidates unseen availability. Incremental scans overlap their prior timestamp. Maintenance enqueues recent scans after ten minutes and full reconciliation after one day. Jellyfin artwork uses an authorised same-origin relay with browser caching only; Coast does not keep Jellyfin images on disk. Scans retain references for Primary, Backdrop, Thumb, Banner, Logo, Art, Disc, Box, BoxRear, Screenshot, Chapter, Menu and Profile artwork when supplied. Cards request images lazily, preserve transparency and fall back to available artwork. Connections show scan counts, percentage when the total is known, and queued/running/completed/failed states. Watched status, resume progress and favourites import from Jellyfin by default. An explicit opt-out remains off, including after reconnecting, and preserves previously imported activity.

Playback requests evaluate the available media sources against the browser codec/container report and current administrator bitrate, delivery and transcode policies. Direct-compatible files retain their codecs through Coast's authorised relay; Jellyfin supplies HLS when transcoding is permitted. HLS playlists replace variant, segment and key URLs with encrypted capabilities tied to one Coast playback session. URLs cannot change origin, leave an approved reverse-proxy prefix or access another Jellyfin item. Range requests pass through. A prepared session does not report viewing activity until the video plays; cancelling its subtitle prompt closes it without tracking or provider reports. Session transitions, progress, completion and configured outbound intent commit together, recording one canonical completion event and one Jellyfin start per playback session. Resuming paused playback restarts opted-in Trakt live reporting. Repeated updates cannot increment play count again, and late progress ticks cannot reopen stopped sessions. Text subtitles are delivered as VTT. Jellyfin-local H264 MP4 trailers use the dedicated persistent hero player without recording viewing history or replacing the title's playback session.

Trakt uses the OAuth device flow and refreshes encrypted user tokens. Refreshes serialize per connection so rotating tokens are not consumed concurrently. Each exchange category is opt-in. Imported history retains timestamps and provider event identities; contradictory changes are retained for user review. Accepting a conflict appends a separate acknowledged event; ignoring it leaves Coast state intact. The original evidence and review decision remain available, and repeated decisions are idempotent. Ratings imported into a previously unrated item never replace a Coast rating. Imported lists retain their origin and survive disconnection. Native tracking, ratings and bulk episode mutations commit their outbound intent in the same PostgreSQL transaction. No-op edits do not export, and bulk actions export only newly changed child events. Outbound history checks the exact timestamp before a retry to avoid duplicate plays; list snapshots preserve ordered membership. A private exported Trakt list description contains a stable Coast reference so a lost create response does not create another list. Live scrobbling and explicit history export avoid double reporting playback when both preferences are enabled.

Personal lists and list items are fully paginated. A season record resolves the season's identity rather than its accompanying show, including ratings, watchlist and list membership. Outbound list reconciliation compares media kind as well as provider IDs, since different media types can share numeric IDs. Season exports require a real external ID accepted by Trakt; Coast's synthetic hierarchy identifiers are never sent as numeric IDs. Current contract shapes were checked against [Trakt's first-party list contract](https://github.com/trakt/trakt-api/blob/master/projects/api/src/contracts/users/subroutes/userLists.ts) and [rating request schema](https://github.com/trakt/trakt-api/blob/master/projects/api/src/contracts/sync/schema/request/ratingsParamSchema.ts).

Seerr requests are sent as the Seerr identity mapped from the user's authenticated Jellyfin account. Coast never accepts a browser-supplied Seerr user ID. Permissions and existing requests are rechecked by the adapter at dispatch. Each linked media-server destination has one standard/4K choice. Local creation, overlap prevention, optional watchlist changes and outbox insertion share a transaction. Up to 20 recently verified title options per connection are retained server-side for 30 minutes, allowing an already opened request to queue during a transient Seerr outage. Cached options require the same active linked Jellyfin identity and current network policy; authentication or permission failures cannot use the fallback. Dispatch always revalidates the live request scope and permissions. Pending cancellation succeeds only while the outbox action can still be cancelled. Seerr status reconciliation refreshes the user's request cache and emits persistent inbox records for state changes.

Current administrator network ports and host allowlists are applied for every call, including playback and artwork. Existing approved instances remain the supported setup path when arbitrary server creation is disabled. Fixed global providers cannot change their hosts. Disconnecting removes credentials and cancels pending/failed actions while preserving imported Coast data. Deleting a Coast account removes its Coast state and links; external account deletion is unsupported by the current adapters and is not attempted.

## Jellyfin sign-in and account management

Settings → Accounts has two independent options, both off by default: create Coast accounts on first Jellyfin sign-in, and sync administrator roles from Jellyfin at each sign-in. The login picker lists only enabled, approved Jellyfin services with a verified server identity. Sign-in rechecks the pinned server identity, authenticates the supplied credentials, and reads the authenticated user's policy. Disabled Jellyfin or Coast accounts cannot sign in.

Existing accounts are matched by their linked Jellyfin user and server, never by their Coast username. Ambiguous existing links require administrator review. New accounts get a unique Coast username, an identity binding and an encrypted Jellyfin access token; Jellyfin passwords are never stored or copied into Coast. Jellyfin validates its own password rules, including short or empty passwords. Local Coast passwords still require 12–128 characters. Administrators can add or reset a separate Coast password through the account editor.

When role sync is enabled, each Jellyfin sign-in grants or removes Coast administrator access to match Jellyfin. Role, password and enabled-state changes revoke existing Coast sessions. The account editor and role sync both prevent removing the last active administrator. Disabling an account keeps its identity and data, preventing auto-provisioning from bypassing the restriction. Deleting an account removes its identity; a later valid sign-in can create it again while auto-creation is enabled.

## Verification and limits

Contract tests cover response validation, regional/original metadata, Jellyfin identity mismatch and partial-page safety, source selection, HLS isolation, Seerr permissions and partial-season duplicate scopes. PostgreSQL integration tests exercise simultaneous provider ingestion, stable episode identities and override preservation. Database tests also verify no-op and bulk exports, atomic rollback when outbox insertion fails, and conflict review ownership/idempotence. Native HTTP fixtures cover MP4 Range responses, encrypted HLS resources and segments, Seerr request delivery, Trakt refresh response validation, selective history import with stable event identities, and a lost history-export response reconciled by a durable retry. These are fixture and database tests, not evidence of live provider compatibility. The Trakt engine fixtures supply a synthetic adapter transport; production OAuth token persistence and account linking still need live-service validation. The reusable `scripts/provider-browser-fixture.ts` launcher is restricted to a disposable `coast_browser_test` database.

Live Jellyfin HLS playback, Coast resume, full scans, TMDB reads and Seerr identity/permissions have been exercised; [Readiness](readiness.md) records the exact evidence and remaining playback limits. The user deferred live Trakt checks and will test real Seerr request mutations themselves. These are not counted as passed checks. TMDB exposes YouTube trailers rather than native video resources; Coast stores that metadata but does not invent a direct stream. Bitmap/ASS subtitle burn-in selection remains unverified; the current player exposes external text subtitles. Hero trailers currently use directly compatible Jellyfin local H264 MP4 files.

API references: [TMDB](https://developer.themoviedb.org/reference/intro/getting-started), [Jellyfin controllers](https://github.com/jellyfin/jellyfin/tree/master/Jellyfin.Api/Controllers), [Trakt API](https://trakt.docs.apiary.io/), [Seerr API](https://docs.seerr.dev/api/seerr-api/), [Seerr API schema](https://github.com/seerr-team/seerr/blob/develop/seerr-api.yml).

TMDB artwork disk caching is optional and off by default. Administrators can enable it under Settings → Policies → Metadata. The cache only accepts fixed TMDB CDN image paths and lives under `artwork/tmdb` in the data directory. Disabling it bypasses existing copies and stops new writes; browser caching remains independent. Stored metadata keeps canonical upstream URLs.

## Conflict resolution

Settings → Connections has a per-user conflict preference: Manual (default), Coast, or a specific connected account. Manual preserves divergent edits for explicit review in Pending actions. Automatic resolution uses Coast's current value or a fresh observation from the selected account, then queues that value to other enabled, compatible destinations. Disconnected, disabled or unsupported preferred services leave conflicts pending. Changing the preference does not enable sync categories or grant provider permissions; it applies when the relevant sync next runs.

Provider baselines retain the last observed and agreed values so simultaneous edits and remote removals are distinguishable. Watch state, favourites and resume positions can return to Jellyfin; Trakt handles its enabled tracking categories and complete list membership/order; Seerr reconciles request statuses and permitted request actions. Jellyfin resume reconciliation uses its [user-data API](https://typescript-sdk.jellyfin.org/functions/generated-client.UserDataApiFp.html), separate from live playback reporting. If a server lacks this operation, durable delivery remains failed/pending with its error rather than pretending the value was delivered. Real Trakt account checks and Seerr request mutations remain deferred.


## Background work

Settings → Jobs separates service maintenance from change delivery. Jellyfin has one shared metadata scan per service, using a stable source account chosen automatically or by an administrator. Delta scans use the previous scan's start time with an overlap; full scans run at their own cadence. Connecting or provisioning a user queues only `jellyfin.sync`, never a shared library scan. The separate user task reads lighter pages for account access, editions, watched history, favourites and resume positions, without re-ingesting known metadata. A title outside the source account's libraries is resolved individually once. User access is never copied from the source account. Availability removals happen only after a complete successful account traversal; interrupted pages retain the last committed cursor and previous availability.

Trakt imports selected tracking categories and lists as separate tasks with independent automatic controls and intervals. Accounts with no selected import categories are skipped. Seerr request reconciliation runs separately from request creation and management. TMDB and IGDB metadata remain on demand and cached; they do not need recurring account scans. Tracking exports and playback reports continue to queue when users make changes.

Scheduling checks run every minute while Coast is running. Automatic pause affects future scheduled work; manual runs and existing jobs remain available. Maintenance inserts and deduplication commit atomically. Pending, running or failed maintenance is reused rather than duplicated, including concurrent connect, timer and manual requests. Each service runs one maintenance task/account at a time across workers and processes; unrelated services continue in parallel. PostgreSQL session locks also protect every connection's action lane during stale-lease recovery. Failed or backed-off maintenance does not hold up other users or later edits; ordered user edits keep their existing retry and review behavior. Service `Retry-After` cooldowns apply to all queued accounts on that integration. Jobs never expire silently. Permanent permission/validation failures need administrator review; transient failures retry with bounded exponential backoff.

The Jobs page groups task cards by service, combining timing, progress and recent runs. Each recurring task has a Schedule dialog; its context menu provides manual runs and run history. Service/type pickers and status filters use the shared row controls. Individual job context menus provide retry and cancel actions. Automatic master/task toggles live in Integrations. Schedule updates merge under a row lock, so independent cadence edits and automation toggles preserve each other. New schedule fields default independently, retaining existing saved master pause states and library/request/tracking cadence. No new production dependencies or job tables are needed.
