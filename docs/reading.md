# Books and comics

Books and Comics are independent, disabled-by-default experiments in **Settings → Policies → Experimental features**. Open Library supplies books and comics, including graphic novels; Comic Vine supplies comic issues. Neither requires Jellyfin. Reading uses Coast's existing media experience, with an optional lazy file reader for PDF, EPUB and CBZ/CBR/CB7/CBT comics (including ZIP/RAR/7z aliases).

## Browse and track

Search combines all enabled media into **Available** and **Unavailable** rows, with shared media-type segments including Books and Comics. Use **Read** in Discover, Library, Continue, Next and Favourites. Books/comics are filters within those shared views, with the usual Shelf headers, cards, menus, skeletons, relationships and pagination. There are no separate browsing pages. Saved details use `/media/{workId}`, including the shared hero and optional detail overlay. Unsaved provider previews resolve to the canonical page when that identity is already stored.

Search renders bounded local results first, then streams enabled provider results without repeating the local query. Media-type segments filter each row locally without navigation or another provider request, following the existing Search shelf pattern. Both rows use Shelf's standard lazy card loading and horizontal scroll. Search stays bounded: deeper provider results require refining the query, rather than paging controls or an additional loading path. Provider-only reading cards carry `available: false`; only observed files on the viewer's connected account set it to true. The shared MediaCard applies the missing-artwork monochrome preference to every medium, never to guests. Comic Vine source attribution remains visible. Discover uses Open Library's trending rank and first-publication-year ordering, and Comic Vine's store-date release feed. Comic Vine has no supported popularity feed; Coast explains that limitation instead of calling recent edits trending. Search/discovery do not import every result or fetch details for every card. Explicit additions initialize Planned only if the user has no existing progress.

Search uses shared relevance across media: normalized exact titles, title prefixes and phrases precede word matches and typo-tolerant matches. Series and authors contribute secondary matches; equal scores retain source order. Local candidate queries use indexed full-text search before bounded hydration. Comic Vine search looks up matching series as well as issue names, then fetches one bounded issue page for at most two series. A successful empty provider response may trigger one broader query; failures and rate limits do not trigger this fallback.

The metadata source does not determine the medium. Open Library subjects identify comics, and either source can resolve to the same saved comic UUID through registered provider identities. An Open Library work's dedicated Comic Vine issue link can register that association during explicit import. Search then resolves both identities in one batched lookup, retaining the saved record and personal progress. Matching names alone never merge a collected volume, edition or issue. If the identities already belong to different saved records, import reports a conflict and preserves both records. Reclassifying an existing Open Library work from Book to Comic retains its UUID and progress.

Library supports the shared Collection, Available, subtype and reading-state filters. Available means an observed file on that user's connected server, not a friend's access or a metadata result. A local file stays in the browser and does not create a server-library availability claim. Continue includes Reading/Paused; Next includes planned reads and explicit saved relationships. Page totals use the common card progress component.

Collection preserves Reading's source/availability filters, and Reading and Paused remain distinct selections. Fresh file observations establish positive availability without waiting for a full movie/show scan. Missing reading-file observations remain Unknown; a screen-library census does not prove that a book is unavailable. Reader cancellation interrupts outstanding decoder waits, and each format removes only its own rendered content when closing or failing.

States are Planned, Reading, Completed, Paused and Dropped. Completion is explicit: the last page does not automatically complete a read. Reopening a completed file preserves completion; Reread explicitly resets bookmarks and starts another reading period. State changes produce dated history and Activity events; page turns update progress without flooding Activity. Existing progress is not backfilled with invented historical events. Ratings, lists, favourites and collection rules use the shared work UUID and category privacy.

Reactions and friend recommendations use shared social controls and category privacy. The notification inbox includes Reading and excludes disabled media from cards and unread counts. Received friend recommendations use the same persistent Recommendations row, Reading segment, subtype filters and recipient-only access rules. Reading participates in cached taste/recommendation signals through subjects, authors, series and personal state. Dropped works contribute negative evidence. Dynamic rows remain lazy and use the same ranking, loading and heading links as other media. Upcoming uses exact comic store dates when present; a book's publication year is not converted into a fictional release day. Author and series labels search their metadata; they are not fabricated person or volume entities.

## Read your own files

Select **Read** on an available saved title to open its accessible linked file directly. The shared server owner prefers the last prepared edition, then the freshest available observation, with stable source/edition ordering. Multiple files do not open a chooser. Metadata-only titles retain details and manual tracking without Read; refresh your library after correcting missing source metadata/access. The reader feature must also be enabled. **Update progress** remains separate manual tracking for physical books or other readers.

Every preparation revalidates live access, exact identity/version and account generation. Only a missing-file 404 permits trying the next known available link, with the negative observation fenced against newer observations/reconnections. Other failures remain explicit; progress never copies across different editions. Existing explicit-source/local preparation contracts remain for internal callers; the normal UI has no local-file/version picker. Local files remain browser-owned with no configured download/input byte cap, with a lazy content-identity worker and no uploaded file bytes. Show app minimizes without ending the session but releases rendering/decoder/compressed-file ownership; Resume reading therefore downloads the archive again. Closing releases resources and saves the final position.

PDF and comic archives synchronize numbered pages. Comic formats retain separate format identities: accepting a RAR alias does not convert it to CBZ or equate differently packaged files. EPUB synchronizes a canonical fragment identifier (CFI), so another viewport can display the same content even when its visual page breaks differ. EPUB's displayed fraction is approximate and does not overwrite the page total of a physical edition.

Only the selected format's renderer is imported when the reader opens:

- PDF uses `pdfjs-dist` with its separate worker and one rendered page. Rendering cancels superseded work, limits resolution and releases page/document resources.
- CBZ and ZIP comics use `@zip.js/zip.js` and natural page ordering. A `.zip` file uses the same CBZ page/bookmark contract; it must contain readable page images. The shared comic source loader downloads one compressed archive per reader open, with no configured transfer byte cap. ZIP indexing, scan inspection and subsequent page reads use that local blob, avoiding a proxy request for every ZIP header and image. Archives are bounded to 10,000 entries, 512 MiB declared expanded size, 32 MiB of actual extracted data per page and 32 megapixels per image. Physical presentation retains only the bounded raster/texture neighborhood described in [Performance](performance.md#physical-reader-ownership).
- CBR/RAR, CB7/7z and CBT (TAR) use `libarchive-wasm` in a format-demanded worker, with one compressed archive (no configured input byte cap), one selected page extraction and no extracted-page cache. Metadata enumeration retains at most 10,000 entries and checks 512 MiB declared expanded size; page reads enforce 32 MiB actual output and the shared 32-megapixel image bound. Paths are checked, duplicate normalized paths rejected, and symlinks/devices never become pages. Archives must match the selected container; damaged/encrypted archives fail explicitly. Solid archives can require decoding earlier data to reach a page. Remote archives use the same cancellable, authenticated comic source loader before indexing. Cancellation/close terminates the worker and its WebAssembly heap; a superseded page can retry through a fresh worker. Each decoder operation has a 30-second execution budget. The WebAssembly and JavaScript worker are self-hosted build assets, never fetched from a CDN.
- EPUB uses `epubjs` with one paginated view. There is no configured compressed-input byte cap. Extraction remains bounded to 256 MiB of actual extracted bytes, 10,000 entries and 32 MiB per entry. Package XML has a separate 2 MiB extraction limit. Declared sizes provide an early check; streaming extraction enforces the real limits before retaining chunks. EPUB.js receives a rebuilt, uncompressed archive of those verified bytes. Duplicate or ambiguous archive paths are rejected. Scripts, forms, embedded frames and event attributes are removed; every supported chapter receives a restrictive content security policy, including chapters without a head element. Unsupported chapter roots reject loading and clear EPUB.js’s cached section, so retrying cannot bypass the hook. Chapter failures settle the reader’s loading/navigation operation rather than leaving a pending display. The content iframe disallows scripts. External manifest resources are rejected and external links disabled.

Reading sessions expire after 24 hours. Foreground reader heartbeats support live activity; progress and bookmarks persist separately from that transient presence. Expired duplicate sessions are pruned after 30 days while retaining the newest bookmark per user/work/edition/format. Reading history persists. Fast page turns coalesce behind one write at a time, and close drains the final position before closing the session.

Kindle (MOBI/AZW/AZW3), DRM, encrypted/multipart comic archives, audiobooks and cross-format location conversion are not supported by these readers. The format boundary follows Jellyfin’s supported list (CBT contains TAR, but raw `.tar` is not an extra accepted extension); recognising a file on the server does not imply that Coast has its renderer. A valid filename does not guarantee that a malformed or unusually large document can render.

## Jellyfin access and imports

Jellyfin is optional for browsing/tracking. Its [book documentation](https://jellyfin.org/docs/general/server/media/books/) describes more formats than Coast's supported readers. Coast reads Book items using authenticated, bounded `/Items` pages and rechecks `/Users/{userId}/Items/{itemId}` before opening or serving a file. Downloads pass through the authenticated Coast session; provider tokens, filesystem paths and download credentials never enter the browser DTO. Requests retain cancellation, byte limits and single-range validation. If Download rejects HEAD with 405/501, Coast probes one byte with GET and immediately cancels the body, preserving full-length or explicit-range HEAD semantics after the same fresh access/version checks.

File identity is separate from metadata identity. A Jellyfin file version is scoped to its server/item and available ETag, modification date, size and path. Opening detects a changed version before serving it. This is a server version identifier, not a byte digest: it does not automatically equate a local copy, another server's copy or a file with incomplete version metadata.

The existing Jellyfin library/user job has a Reading phase. It maps verified Open Library work IDs, resolvable edition/ISBN identifiers, exact Comic Vine issue IDs (`4000-…`, including the plugin's slug/issue permalinks), or a previously explicit file link. Titles and filenames never merge works; a Comic Vine volume or ambiguous numeric ID is not an issue. Verified metadata is imported even when a file's format is unsupported, so those titles can appear in Library with Collection and Available off. Supported PDF, EPUB and CBZ/CBR/CB7/CBT files (or their archive aliases) establish reader editions and availability. Previously unsupported CBR/CB7/CBT files gain observations on the next Reading import; installing a decoder alone does not invent access. Files without verified identifiers are not automatically linked: correct their source metadata and refresh. Explicit linking remains an internal API contract, not a normal Read chooser. Shared catalogue imports never grant another user's access; availability remains account/generation scoped.

Each observed item commits before saving its durable Reading cursor and yielding to the common job scheduler. Skipped/unsupported files advance that cursor too. Personal onboarding does not add a full Book scan; normal background access jobs and supported companion Book updates use the same mappings and permission fences. Incomplete scans do not publish final removals.

Open Library references accept bare work/edition IDs, paths and exact Open Library URLs. Jellyfin file GUIDs normalize casing and hyphens at the provider boundary; indexed lookups reuse an existing file link rather than creating a second edition. The provider-item GUID index covers reading as well as music.

A missing metadata record is logged and skipped without blocking later files. Authentication, rate limits, timeouts and server failures still stop the scan for the existing retry policy. If a linked file starts claiming a different verified title, Coast preserves the original link and personal progress, records the conflict and holds file availability as Unknown. Reader access and party source selection reject held editions. Correct the Jellyfin metadata and rescan to restore the verified original identity; removing the identifiers does not clear the hold. Coast does not silently move progress to another work.

## Reading parties

Opening a reader can become the current item in the existing party. Members use their own authorized source: previously linked accessible files can be resolved automatically, while local readers must open their own matching copy before joining. Party state includes work, format, edition and location; matching titles or page totals alone are insufficient.

The same controller permissions and revision checks apply to page changes. Guests follow the shared location, including EPUB link navigation. Changing between video, music and reading clears incompatible source/queue/location state. Reading menus omit playback-time offsets, buffering and ready-check controls. Leaving follows the existing Keep reading preference. Parties do not distribute the host's file or grant a guest access to its server.

## Provider setup and terms

Open Library needs no key. Comic Vine requires an administrator-owned integration in **Settings → Integrations**, with encrypted server-only credentials; users do not link Comic Vine accounts. Saved metadata and progress remain usable during provider outages. Disabling an experiment filters shared reads before pagination and rejects its operations without deleting stored data.

Comic Vine allows **non-commercial use only**. Its source link appears with its metadata and remains in public DTO attribution. Review its [official API terms](https://comicvine.gamespot.com/api/) before commercial use. Open Library recommends application identification and a real contact address for regular traffic; Coast identifies its project and uses conservative pacing, but does not invent an operator email. See its [usage guidelines](https://openlibrary.org/developers/api).

Provider queries use the existing fixed-origin transport, priority lanes, cancellation, cooldowns and single-flight caches. Open Library requests are spaced at 1.1 seconds, Comic Vine at 18.1 seconds. These process-local limits do not constitute a distributed quota. Responses are capped at 2 MiB; normalized descriptions and covers are bounded and provider URLs constrained. Open Library search fetches 20 works per page. Comic Vine fetches up to 10 issue-name matches and 10 series issues, deduplicated by issue identity. Series lookup uses one request and one batched issue request when a matching series exists, with at most one additional empty-result fallback. Local hydration uses the shared 60-item bound. Search/discovery/detail caches remain bounded; network metadata lookups finish before canonical or personal transaction locks.

## Collections and editions

Verified Comic Vine volume identities (`4050-…`) group their separate issues (`4000-…`) in shared `reading_groups` and `reading_group_members` records. Importing an issue records its provider-supplied volume and issue position; correcting that relationship replaces the old membership for that provider. It never merges the issues into the volume work or groups by similar titles. Comic detail pages unpack their verified volume directly into an issues row named after that run, with its title linked to the full volume page. An older saved comic enriches only that exact issue when needed, including a verified Comic Vine alias on an Open Library work. Both the row and volume page load ten provider issues at a time through the shared Shelf source; existing saved issues hydrate together with the viewer's own state. No generic Collections card is needed to reach sibling issues.

Comic Vine's volume detail for `4050-138023` was checked against the configured integration on 17 October 2026. It supplies the run identity, title, cover, description, publisher, start year, issue count and explicit issue membership. That supports a series/run detail page. The inspected response has no parent-series identity or related-volume membership linking relaunches, spin-offs or collected editions; characters, concepts and title similarity are insufficient evidence for an automatic franchise-wide rollup. Those broader groupings need verified links or explicit curation.

The [collection-provider investigation](audits/2026-10-17-comic-collection-providers.md) verified the complete Harley Quinn parent/collected-volume/issue chain through GCD's beta v2 API, with production availability and cross-provider identity gaps recorded separately. Metron and Hardcover were also assessed. These are proposed enrichment sources, not enabled integrations.

Open Library editions are alternate publications of one work, listed twenty at a time from the work's editions endpoint. Each edition must declare the requested work relationship. Edition cards link to their provider record; listing an edition does not imply file access, select a reader file or create another tracked work. A book series needs a stable provider-supplied group identity and ordered membership; Open Library's unstructured series text alone does not establish one, so automatic book-series grouping is not enabled.

These supplemental rows use bounded shared provider caches and normal request-priority lanes. They activate on demand, cancel stale client ownership and preserve horizontal occurrence order. The collection page uses the same MediaDetails, Shelf, MediaCard and section navigation as the other media. Migration `0060_reading_groups.sql` adds the group records and content-revision triggers; importing unchanged metadata does not churn revisions.

## Code boundaries and API

`reading/model.ts` owns shared identity/state/location contracts. Provider adapters validate remote responses; `providers/reading.server.ts` supplies metadata transport/cache composition. `catalogue/reading.server.ts` owns canonical ingestion; `catalogue/reading-files.server.ts` owns exact file links and guarded availability. `core/reading/service.server.ts` owns personal mutations. `reading/query.server.ts` owns bounded read models, and `reading/sessions.server.ts` owns authenticated file sessions. `sync/jellyfin-reading.server.ts` composes imports within the existing queue. UI uses the shared Shelf, MediaCard, MediaDetails/MediaHero, DetailOverlay/Dialog, Button and progress components; reader engines are lazy format-specific modules.

Browser routes under `/api/v1/reading` provide explicit imports, progress, history, linked-source candidates, source selection, collections/editions and session lifecycle. Public `/api/public/v1` exposes enabled reading Catalogue/Collection/Library/Progress reads, owner-only paginated history and idempotent `reading:write` progress changes. `reading.changed` webhooks commit with the mutation. Public tokens do not open files or expose provider credentials; see [Public API](public-api.md).

## Verification and remaining acceptance

Provider/model/hash tests cover identity, bounded payloads, format locations and streamed hashing. Disposable database tests cover permissions, account generations, import resumption after yields, no-op writes, history, rereads, party controllers/revisions, scope/idempotency/webhook behavior, shared availability and cached recommendation signals. Run database tests through `scripts/test-database.ts`, never against live data.

Production-build browser fixtures exercise PDF, EPUB and CBZ on desktop and mobile, close/resume, lazy loading and two-browser page synchronization. Additional archive fixtures verify actual RAR4, 7z and TAR decoding, ordered/duplicate page navigation, worker cancellation and fresh-worker retries. Disposable database checks cover all new archive formats in imports, linked sources, availability, bookmarks and party locations. Migration `0061_reading_archive_formats.sql` extends session and party format constraints without changing existing bookmarks. Synthetic fixtures do not certify every real document, a deployment Comic Vine key or a live Jellyfin book/download configuration. Those deployment checks, richer author/series entities, additional formats and cross-source edition identity remain explicit follow-up work.

### Shared detail rows

Reading uses the same `MediaDetails` composition and provider-neutral `MediaDetailRows` renderer as other media. Insights includes Overview, concrete personal page progress, and privacy-filtered Coast community totals. Credits uses the shared circular person cards; saved Comic Vine issues lazily enrich writers with the remaining supplied contributor roles. Author-only metadata still works without that provider. The Details panel retains the metadata source link and known page count. Related titles are local catalogue matches by author/subject, ranked before pagination and hydrated only for the requesting account's page. Editions and verified issues remain the normal demand-loaded Shelf sources. Comic-volume detail pages show known-issue, available, reading and completed counts, with an explicit partial-catalogue explanation.

Written provider reviews are omitted where the selected reading providers do not supply them; no placeholder scores, reviews, reading duration or inferred collection relationships are manufactured. Migration `0062_reading_detail_candidates.sql` adds GIN indexes for author/subject related-title matching. Reader controls and the broader reader/music controller redesign remain a separate roadmap task.

All media details use one shared Activity row with the cards from For You, filtered to the selected title or verified container membership before grouping and cursor pagination. The row includes your activity and permitted activity from friends, including reading-page details and reactions. Its shared relationship segments also retain current reading, saved, list and favourite states without inventing event history. Personal reading history remains stored for progress and the public API; there is no separate Reading history row.


### Physical book/comic presentation

`Reader.svelte` retains Coast's session, heartbeat, save and party owners. PDF and every comic archive format use `reader/physical-reader.ts` to translate those contracts into the shared typed model under `reader/physical/`. PDF.js and the existing archive decoder remain the file owners. EPUB retains its sanitized reflow surface and CFI/fraction locations.

The physical canvas has no lab toolbar, authentication, storage, shelf or tuning UI. It sits at layer 70 above app content, beneath navigation at 80 and media controls at 90. A click/tap outside the actual model dismisses through Coast's close flow; an outside drag still rotates/unfocuses. The canvas dims app content with Coast's dialog scrim. Coast's navigation reading button switches between the reader and app; Escape closes the session. Click/drag and keyboard arrows turn pages, including bounded cascades. Opening starts closed and focused, using the 20° closed, 10° open, 0° reading preset. Opening the cover resumes the saved spread. Party followers receive the room's page directly and cannot curl to another page locally.

Every comic scan is inspected for clear double-width images, using dimensions without drawing an inspection canvas. Settled/late-aborted bitmaps close; actual face canvases are made on demand. Split faces map to the same original archive page/total for saves and parties. **Settings → Appearance → Sanitize odd page counts** is enabled by default, retaining intentional removal of an unmatched final face after spread splitting and the original last-face location behavior. Disable it to preserve every scan/half and add unprinted faces for an even, minimum-four-face binding before the actual back cover/final wraparound pair. Unprinted faces have no saved location and original totals do not change. The preference applies on the next reader open and resets to enabled with other personal preferences. PDF retains its separate unprinted odd-binding face. External navigation is serialized, superseded queued locations are discarded, and it does not echo into saves or room commands.

Renderer construction registers resources before later setup can fail; rejected setup and ordinary disposal share the same cleanup owner, including explicit WebGL context release. See the [focused actual-data audit](audits/2026-10-19-reading-performance/README.md) for measured gains, teardown cost, rejected native batching and remaining loading/format/device checks. Count bounds do not establish a decoded-byte or GPU-memory plateau; image admission currently checks pixel count after decode.

The local-only `experiments/comic-lab` host uses the same physical presentation for focused tweaks. Its independent Jellyfin session, local resume and tuning controls never enter Coast's reader path. The lab and its rollback checkpoints stay outside Git and container builds.

Loading text and the shared progress bar show actual download bytes and checked-page counts above the fade. Unknown stages are indeterminate. At render preparation the indicator disappears and the physical backdrop blurs, while the reader/navigation stay sharp. Reading sessions participate in user presence and admin Active streams/History with page-based positions; page turns do not add Activity history. Reading parties require each viewer’s own matching source, and public playback share links do not distribute reading files. See [loading and integration acceptance](audits/2026-10-19-reading-performance/loading-and-integration.md) and the [delivery investigation roadmap](audits/2026-10-19-reading-performance/investigation-roadmap.md).
